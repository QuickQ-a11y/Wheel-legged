# 遥控键位与模式分配

> 范围：**跨板**。本文是键位语义的唯一权威，代码里的映射表（`chassis_remote.h`
> 的 `CHASSIS_MAP_*`）按本文实现。通道到硬件的对应关系在 `Gimbal/CLAUDE.md`
> §遥控后端，那边是唯一权威，本文不重复。

发射机 **FS-i6X** + 接收机 **FS-iA10B**，接在云台板 UART5。
底盘不接接收机，遥控输入由云台经 FDCAN3 转发。

**本文的键位语义与传输协议无关**：同一台 FS-iA10B 既可走 i-BUS 也可走 S.BUS
（当前默认 S.BUS），DR16 后端也还在。三个后端解出的都是同一份归一化 `Remote_t`，
下面这套映射完全一样。协议差异见 `../Gimbal/CLAUDE.md` §遥控后端。

---

## 1. 为什么是这套分配

**约束：发射机要求所有拨杆位于 UP 才允许开机**（否则报警）。所以 UP 是唯一保证的
上电初始状态，**必须映射为最安全的模式**。这条决定了 SwC 的方向，而 SwC 的方向
与旧的 DR16 右拨杆（下=急停）**相反**。

**硬件限制：i6X 出厂只有 SwC 是三档**，SwA / SwB / SwD 都是两档。
早先的交接文档把"底盘需要两个三档"列为阻塞项，本方案通过把"允不允许动"和
"做什么"重新切分，让三档只用在使能级上，**阻塞项因此消解**：

- 不需要换三档开关模块
- 不需要再改发射机菜单（SwA~SwD → CH7~CH10 已分配完毕）

## 2. 键位总表

### SwC —— 使能级（唯一的三档）

| SwC | 云台 | 底盘 |
|---|---|---|
| **UP** | 卸力 | 卸力 + 急停（`remote_stop_flag = 1`） |
| MID | 正常控制 | `ZERO_FORCE`，电机全软可搬运摆姿态 |
| DOWN | 正常控制 | 由 VrA 组 + SwA/SwB 决定，进 STANDING 与倒地自起检测 |

`REMOTE_SWITCH_UNKNOWN` 与 UP 同等对待（急停）。通道值残留 0 时
`IBUS_ConvertSwitch` / `SBUS_ConvertSwitch` 给出 UP 一侧，退化方向是安全的。

> **UP 和 MID 对电机输出都是零，区别在哪？**
> UP 走 fault 路径：`remote_stop_flag` → `CHASSIS_FAULT_REMOTE` → `safe_flag` → 清零命令。
> MID 走模式路径：`CHASSIS_MODE_ZERO_FORCE` 在 `Chassis_State_Update` 里优先级最高，
> 会同步 `last_mode` 并**清空 `Chassis.fault`**，所以它同时是"万能出口"——
> 任何卡死状态拨到 SwC 中都能把车拉回零力矩。
>
> ⚠ **正因为 ZERO_FORCE 会清 fault，急停和掉线时不能顺手把 `Chassis.mode` 压成它**，
> 否则 `CHASSIS_FAULT_REMOTE` 会被一起抹掉，Watch 上就看不出遥控丢了。
> 现在的实现是：急停/掉线只关许可 + 回中目标，**模式保持不变**。
> `test_chassis_remote.c` 的 `testOffline` 钉死了这条。

### SwC = DOWN 时：VrA 选组，SwA/SwB 在组内选模式

**VrA 低组**（`knobA < -0.15`）：

| SwA | SwB | 模式 |
|---|---|---|
| UP | UP | `FOLLOW`（STANDING，底盘跟随云台） |
| DOWN | UP | `TOP`（小陀螺） |
| UP | DOWN | `STEP`（台阶） |
| DOWN | DOWN | `FOLLOW` ← 冲突回落 |

**VrA 高组**（`knobA > +0.15`）：**SwB 主导**

| SwB | SwA | 结果 |
|---|---|---|
| DOWN | 任意 | `FOLLOW` + 跳跃请求（`goal.jump_flag`，上升沿跳一次，见 §5.1） |
| UP | DOWN | `FOLLOW` + 腿长 `APP_RC_LEG_CROUCH`（压缩腿） |
| UP | UP | `FOLLOW`（STANDING） |

> **两组的冲突处理刻意不对称，这不是笔误**：低组里小陀螺和台阶是两个互斥动作，
> 两个都拨下去无从判断要哪个，回落 `FOLLOW`；高组里跳跃本身就包含压腿蓄力，
> SwB 直接盖过 SwA，不存在冲突。

**滞回**：VrA 落在 ±`APP_RC_KNOB_HYST`（0.15）之间时保持当前组。不加滞回的话
旋钮停在中值附近时噪声会让模式反复横跳。用户明确要求"随时可切组"，
所以**不**检查 SwA/SwB 是否已归位。

**SwA/SwB 只判 DOWN，MID 和 UNKNOWN 一律当 UP。** 这两路挂的是两档开关读不出 MID，
DR16 降级映射还会留下 UNKNOWN，这么写让两种情况都落到不激活的一侧。

### SwD —— 自瞄

UP 关 / DOWN 开。SwC 在 MID 和 DOWN 时都可进自瞄。
自瞄 + SwC DOWN 时**底盘不跟云台，航向锁死在进自瞄那一拍的值**。

### VrA / VrB 摇杆与旋钮

| 控件 | 用途 |
|---|---|
| 左摇杆 Y | 前进速度（`TOP` 下左摇杆 XY = 二维平移） |
| 右摇杆 X | 偏航角速度（跟随云台时不参与；自瞄时也不参与） |
| 右摇杆 XY | 云台 YAW / PITCH |
| VrA | 底盘模式组选择（**不再是腿长三档**） |
| VrB | 摩擦轮 + 拨盘（云台独有，不下发底盘） |

**VrB 分段**（比较的是归一化值，换算见 `app_config.h`）：

| VrB (us) | 行为 |
|---|---|
| 1000~1500 | 摩擦轮关、拨盘不使能 |
| 1500~1990 | 摩擦轮开 |
| 1990~2000 | 拨盘使能 |

拨盘使能后：**非自瞄时直接转动发弹；自瞄时交由上位机火控标志位控制。**

**单发 / 连发**：进入使能区间立刻发一发（单发）；持续保持超过
`APP_SHOOT_BURST_DELAY_MS` 后转连发，按 `APP_SHOOT_BURST_HZ` 连续发射；
退出使能区间时计时复位。

### 腿长

原先拨轮选三档（`APP_RC_LEG_S/M/L` = 0.28/0.18/0.38）。VrA 被征用为模式组
选择器后三档取消：

- 正常行驶恒为 `APP_RC_LEG_M = 0.18`（原拨轮中位值，也是上电默认值）
- 只有高组 SwA 打下去才换成 `APP_RC_LEG_CROUCH`

> ⚠ `APP_RC_LEG_M` 名字里的 M 指**原拨轮中位档**，不是"中等腿长"——它其实是
> 三档里最短的。留着这个名字是为了不动历史整定数据的口径。
>
> ⚠ `APP_RC_LEG_CROUCH` 只是 i6X 高组的一个固定腿长档，**和跳跃无关**：跳跃蓄力用的是
> 独立的 `Chassis_Config.jump.charge_L0`（§5.1）。早先"等跳跃实现时再定压缩量"的说法作废。

## 3. DR16 / DT7 降级映射

DR16 后端**保留**（`APP_REMOTE_BACKEND` 编译期三选一），但整套语义是按 i6X 的
四拨杆两旋钮排的，DT7 凑不齐：

| DT7 控件 | 映射到 | 说明 |
|---|---|---|
| 右拨杆（三档） | `SwC` | 使能级，语义完全一致 |
| 左拨杆（三档） | `SwA` | **UP = 跳跃请求**（模式仍是 `FOLLOW`），MID = `FOLLOW`，DOWN = `TOP` |
| 滚轮 | `VrA`（即 `knobA`） | **三档腿长**，见下 |
| — | `SwB` / `SwD` / `VrB` | 无对应物理控件，恒为 `UNKNOWN` / `0` |

⚠⚠ **滚轮的职责按数据源分，这是 DT7 与 FS-i6X 唯一语义不同的地方：**

| 数据源 | `knobA` 的用途 | 模式组 |
|---|---|---|
| 底盘**本地插的 DT7/DR16** | **三档腿长**（`APP_RC_LEG_S/M/L`，阈值 `APP_RC_DIAL_THRESHOLD`） | **锁死低组** |
| 云台经板间 CAN 转发的 **FS-i6X** | 选模式组（`APP_RC_KNOB_HYST` 滞回） | 由 `knobA` 选 |

DT7 只有一个滚轮，"选组"和"调腿长"挤不到一个旋钮上。选了腿长是因为
高组在 DR16 上只多给两样：压缩腿（本身就是一个固定腿长，滚轮够得到）
和跳跃（`SwB` 在 DR16 上恒为 `UNKNOWN`，本来就到不了）。跳跃因此在本地
DR16 上**改由左拨杆打到最上**触发。

⚠ **"左拨杆 UP = 跳跃"只属于本地 DR16。** i6X 的 SwA 在 UP 是常态（上电要求全部
拨杆在上），那条路上这么判，一站起来就会跳。判据同样是 `local_dr16`，
`test_chassis_remote.c` 的 `testLocalDr16LeftUpRequestsJump` 钉死了两条路的区别。

判据是设备层的 `Board_IsOnline()`——`task_remote.c` 选源用的也是它，
所以不存在第二份事实，也不需要编译期开关（底盘那份 `app_config.h` 里
**没有** `APP_REMOTE_BACKEND`，它根本不知道云台挂的是哪台发射机）。

**结论：DR16 后端只能到达 卸力 / 只动云台 / STANDING（可调腿长） / 小陀螺 / 跳跃。**
台阶、自瞄、发射都进不去——退化方向是安全的。
`test_dr16.c` 的 `testGenericInputMapping` 钉死了 `SwB`/`SwD`/`VrB` 必须停在
不激活的一侧。

## 4. 板间协议

两帧走 FDCAN3，帧长封顶 8 字节（`FDCAN_FRAME_CLASSIC`）。字节布局是
`app_config.h` 的板间通信注释块，**那里是权威**，本文只说设计取向。

**架构：每块板只解释自己关心的开关，板间仍然只传归一化后的原始快照。**
不在云台上解析出 `Chassis_Mode_t` 再下发——那会让云台知道底盘的模式语义
（反向依赖），而且把 `Chassis_Mode_t` 变成必须两侧同步的第二份协议常量，
正是根 `CLAUDE.md` 警告的漂移源。

各板消费的控件：

| 控件 | 云台 | 底盘 |
|---|---|---|
| SwC | ✅ 外层状态 | ✅ 使能级 |
| SwA / SwB / VrA | 只转发 | ✅ 选模式 |
| SwD | ✅ 自瞄 | 通过 flag 位间接用 |
| VrB | ✅ 摩擦轮/拨盘 | **不下发** |
| 右摇杆 | ✅ YAW/PITCH | ✅ 偏航角速度 |
| 左摇杆 | 只转发 | ✅ 前进/平移 |

⚠ `APP_BOARD_FLAG_AUTOAIM` 送的是**云台解析后的结论**而不是 SwD 原始位置：
上位机掉线时 SwD 打下去不该让底盘锁航向。
**当前实现只做了"拨杆在位"这一半**，`task_usb` 目前只有累计计数器、
没有最近一帧的时间戳，补在线判定属于自瞄那一摊活。

## 5. 跳跃（已实现）与长期计划

5.1 已实现（2026-09-27，⚠ 还没上实机）；5.2、5.3 仍是未完成项。

### 5.1 跳跃

**跳跃不是模式。** 映射层只给一个请求电平 `Chassis.goal.jump_flag`，模式照旧是
`FOLLOW`；控制层取它的**上升沿**，在站立里做一次跳跃动作（`CHASSIS_JUMP` 状态），
做完回 STANDING。所以 `chassis_remote.c` 仍然是纯电平跟随，边沿只在
`Chassis_State_Update` 取一次。

| 触发 | 本地 DT7/DR16：左拨杆打到最上；FS-i6X：高组 SwB 打下 |
|---|---|
| 门槛 | 必须已连续站立满 `jump.stand_time`；没站满时这个边沿**作废**，不留着补跳 |
| 不连跳 | 跳完拨杆还停在上面没有新边沿，要拨下再拨上 |
| 冷却 | 跳完经 `State_Enter(STANDING)` 重新计时，`stand_time` 同时就是冷却 |
| 中途拨模式 | 推迟到回站立之后处理；**只有 SwC 拨中（零力矩）立即生效** |
| 急停/卸力 | `Remote_Hold()` 撤掉请求，恢复运行那一拍不会凭空多出一个边沿 |

⚠ **与早先设计的差异**：原计划是"mode=JUMP + 跳完锁存 FOLLOW，拨回才解锁"。改成
flag 边沿之后不需要锁存和解锁逻辑，跳完 mode 也不用切回来，`CHASSIS_MODE_JUMP`
已删除。上电时拨杆就在上面也不会跳——那一拍还没站满。

**五相**（取自ZJU §13.8，参数全在 `Chassis_Config.jump`，每相都有超时）：

| 相 | 动作 | 退出 |
|---|---|---|
| CHARGE 蓄力 | 腿长按斜坡压到 `charge_L0`，完整平衡 | 到位且腿速 < `still_d_L0`，或超时 |
| EXTEND 起跳 | **开环**轴向力 `extend_F0`，**不扣气弹簧**；LQR 屏蔽位移和速度 | 两腿都伸过 `extend_L0` → 空中；超时 → 直接 RECOVER（没跳起来，不能在地上关轮子） |
| RETRACT 空中收腿 | 收到 `air_L0`，重力前馈换成 −(m_leg+m_wheel)·g，**轮子关**，只留腿摆通道 | 到位保持 `retract_hold`，或超时 |
| LAND_PREP 等落地 | 伸到 `land_L0`；进本相先把两腿判成离地（`Chassis_Ground_Mark_Off`） | 离地观测判两腿都触地且过了 `land_min`，或超时 |
| RECOVER 落地缓冲 | 锁住触地时的腿长和位移，LQR 只屏蔽位移 | `recover_time` 后交回 STANDING |

⚠ **`land_L0` 不能低于 `lqr.L0_max − observer.land_L0_margin`（现为 0.32）**：
触地判据B是"伸腿速度从峰值回落"，腿在空中伸到目标、自然减速时也满足它，
只有停在那条线以上判据B才关掉。这就是ZJU空中把腿一直推到接近最长的原因。

⚠ 触地判据里有一路是支撑力比例（`land_force_ratio = 0.35`），而腿轴有约 ±40 N 摩擦
（见气弹簧实测），在空中也可能误判成触地。**架空测试第一件事就是看 LAND_PREP
会不会不等超时就退出**——架空时车永远落不了地，正常应该熬到 `land_timeout`。

**参考各校的取舍**：

| 环节 | ZJU | SPR | 同济 | 本车 |
|---|---|---|---|---|
| 触发 | 站稳N拍 + 冷却 | 电平，跳完停在 READY 等清标志 | 按住蹲、松开跳 | 上升沿 + 站满（兼冷却） |
| 起跳 | 开环关节力矩，不补弹簧 | 闭环腿长PID目标0.4，关弹簧补偿 | 抬目标腿长和轴向力 | 开环**虚拟腿**力，不扣弹簧 |
| 空中 | 收腿 + 腿保持竖直 + 轮子关 | 收腿后固定等 220 拍 | SHRINK | 同ZJU，收腿长度按弹簧重定 |
| 落地 | 判据A/B | 固定延时 | — | 复用观测器的A/B + 超时 |

⚠ 跳跃与气弹簧、MPC 的交互：起跳相不扣弹簧（SPR 的教训：不关补偿的话 0 N 和
450 N 的弹簧跳得一样高）；跳跃期间一律走 PID 路径，`mpc_flag` 不生效。
`Observer_In_Action` 包含了跳跃，整车离地的通用动作在跳跃里不插手。

### 5.2 自瞄

- 已有：`Gimbal.autoaim_flag`（由 SwD 派生）、板间 `APP_BOARD_FLAG_AUTOAIM`、
  底盘航向锁死（`chassis_control.c` 的 `autoaim_flag` 分支）
- 已有的上位机接口：`usb_control_payload_t = {float yaw; float pitch; uint8_t shoot;}`，
  `task_usb.h` 的 `recentControl` 存着最近一帧
- 缺：云台去消费 `recentControl` 的 yaw/pitch；上位机在线判定

**思路**：自瞄激活时，云台目标角度改为上位机下发的角度（而不是右摇杆积分），
开火时机由 `shoot` 标志位决定。

### 5.3 摩擦轮 / 拨盘

**硬件已定案并与旧描述不同**：四台全是 **M2006 + C610**（三个摩擦轮，不是两个 M3508），
拨盘物理装在底盘上、挂 FDCAN3。总线分配和 C610 与 C620 的差异见 `../Gimbal/CLAUDE.md`。

- **已实现**（2026-09-24）：`Shooter` 独立模块（跑在独立的 `shooter_task` 上）、
  四台电机的收发、三个摩擦轮的 PI 速度环、按总线分的两个输出门、
  `SHOOTER_FAULT_ESC` 接了 C610 的堵转码
- **已实现**（2026-09-24 第二步）：**VrB 接进控制**；拨盘串级环（位置环→速度环，
  输出轴口径）；单发/连发状态机（就是本节上面那套 `APP_SHOOT_BURST_*` 语义）；
  防卡弹状态机（堵转码 ‖ 电流饱和 → 退弹 → 连续失败则放弃）。
  ⚠ **一次都没上实机**，`APP_SHOOT_AMMO_PER_ROUND` 和 `APP_SHOOT_TRIGGER_DIR`
  都还是占位值。
- 缺：热量与火控（**没有裁判系统，热量没有真值**，暂不做）；自瞄开火

## 6. 实机验证清单

架空、`Chassis_Config.output.*_flag` 先置 0，按
`Chassis/Codex文档/实机调试检查清单.md` 走。

1. 上电四杆全 UP → `Chassis.remote_stop_flag == 1`，`Chassis.fault` 含
   `CHASSIS_FAULT_REMOTE`，`output.T_joint` / `I_wheel` 全零
2. SwC 逐档拨：MID 清 fault 进 `ZERO_FORCE`，DOWN 进 STANDING
3. 低组走一遍四种 SwA/SwB 组合，核对 `Chassis.mode` 与 §2 的表一致
4. 高组：SwA DOWN 看 `Chassis.goal.L0` 变成 `APP_RC_LEG_CROUCH`；
   SwB DOWN 看 `Chassis.goal.jump_flag == 1`、`Chassis.mode` 仍是 `FOLLOW`
   （本地 DR16 上对应的是左拨杆打到最上）。跳跃本身的上机步骤见 §5.1
5. VrA 在中值附近来回扫，确认 `Chassis.knob_group` 不抖
6. SwD 拨下，确认 `Gimbal.autoaim_flag` 和底盘 `Chassis.autoaim_flag` 都置位，
   且底盘航向不再跟云台
7. VrB 缓慢拧到底，确认 `Gimbal.fric_flag` 在过中位时置位、
   `Gimbal.trigger_flag` 在接近端点时置位（**这一条要实测 VrB 的真实端点值**）
8. **拔掉 FDCAN3 线**，确认 `Chassis.remote_online_flag` 归零、
   `CHASSIS_FAULT_REMOTE` 置位、两路输出全零
