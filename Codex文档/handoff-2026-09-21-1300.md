## 1. ⚠ DM MIT 力矩标度错配（最重要，两块板都涉及）

`APP_DM_TOR_MIN/MAX` 必须与电机里烧的 **TMAX 寄存器**逐位一致。底盘电机烧的是 **40**，
而固件长期是 ±15、中途被改成 ±25：

| 固件量程 | 命令方向 | 反馈方向 |
|---|---|---|
| ±15 | 实际 = 命令 × **2.667** | 读到 = 真实 × **0.375** |
| ±25 | 实际 = 命令 × **1.600** | 读到 = 真实 × **0.625** |
| ±40 | 1.000 | 1.000 |

**为什么藏了这么久——这条最该记住**：两个误差在往返上**精确相消**
（命令 10 → 实际 15.99 → 读回 9.99）。把 `output.T_joint` 和 `dm_motor[].torque_nm`
摆在一起对比**永远是对的**，而这恰恰是唯一查不出本类错配的检查。**别再用它当证据。**

**唯一可靠查法**：绝对力参照。架空、关节输出开、腿长 PID 稳在竖直位，在轮轴挂一个
称过的重物，看 `Chassis.ground.force[].F0` 的变化量是否等于 `m·g`。

底盘已改成 ±40。**云台是 DM4310、`APP_DM_TOR ±10`，还没跟寄存器核对过**——同样的坑。

连带后果：K 的**轮子两行走 DJI 电调，口径一直是对的**；**腿摆两行走 DM，被同一系数放大过**。
所以历史整定里轮子/腿摆的相对增益是失配的，这很可能就是腿摆偏躁的根源。

## 2. 质量口径重标（推翻了 body_mass = 6.7）

旧值 6.7 是从"稳态 `leg[].F0` = 31/35 N"反推的，但那是**命令值**、且当时被放大 2.67 倍
——整条推导链不成立。

**整车称重 20.8 kg** → `body_mass = 20.8 − 2×1.65 − 2×0.537 = 16.43`。
`I_roll` 同步 `16.43 × 0.22² = 0.7950`。`ABK_LQR.py` 的 `m_b_ac` 同步，四块系数重出。

静力学说单腿髋部承担 80.6 N，**实测稳态 F0 是 97.5 N**（左 85~95、右 100~110），
差 16.9 N 是真实的未建模力（髋部分担的腿自重 + 五连杆轴承/同步带静摩擦）。
用 `F0_gravity_scale = 1.21` 吸收。

⚠ 摩擦那部分**不是恒力**（总是反抗运动方向），按常量补偿在静止和伸腿时对，
收腿时会略微过量。收腿偏快就往回调这个系数，**别动 `body_mass`**——那是称重定死的。

## 3. MPC 稳态误差：`F_eq` 与模型常量项必须同源

`chassis_mpc.cpp` 原来 `F_eq = 0.5·M·g`、`fdyn = -g·Ts`。加了 `F0_gravity_scale` 之后
**两处必须一起改**，否则代价函数的 `Uref` 和模型的平衡点互相拉扯，结果是**又一个稳态误差、
方向相反**：

```c
const tinytype F_eq = 0.5f * M * g * Chassis_Config.F0_gravity_scale;
fdyn << 0, 0, 0, -(2.0f * F_eq / M) * Ts;     /* 原来是 -g * Ts */
```

改完标称闭环零稳态误差、超调 2.2%、0.43 s 收敛。

**`mpc.damping` 不是阻尼旋钮**：它是被控对象模型里的物理阻尼（进 `Ad(3,3)`，本车量级
只有 0.01），而且方向相反——调大等于告诉 MPC"对象自己会衰减"，MPC 更不愿出力压速度。
同理 **`lqr_Q[9]`（俯仰角速度权重）加大不改善阻尼**，实测 5→1000 阻尼比恒为 0.77、
恢复时间 0.28→0.74 s，只会变钝。

## 4. ⚠ 四块系数必须同一次运行产出

`lqr.coefficients`（K，240）和 `leso.{Ad,Bd,L}_coefficients`（600/240/840）
**出自 `ABK_LQR.py` 的同一次运行**。BIG 块 `leso.comp_scale = 1.0`，补偿足额接入，
K 和 LESO 用不同模型会直接打架。

那三个 `print_block` 原先是注释掉的，导致"只重出 K"这个错误特别容易犯，现已默认全输出。
粘完核对元素数 **240 / 600 / 240 / 840**。

## 5. 气弹簧：选型结论**反转**了

早先写的"偏硬 3.3 倍、站立时电机要反向拉腿、理想标称力 103~130 N" **全部作废**——
那是拿 `body_mass = 6.7` 比的。按 97.5 N 的真实需求重算：

| L0(mm) | 145 | 175 | 265 | 325 |
|---|---|---|---|---|
| `F0_spring`(N) | 87.5 | 94.2 | 108.0 | 111.3 |
| 占需求 | 90% | 97% | 111% | 114% |
| 关节力矩 无→有 | 10.3→**1.06** | 12.1→**0.41** | 14.0→**1.50** | 13.2→**1.87** |

**弹簧选得很准**，电机只补 ±14 N，站立关节力矩降一个数量级。这也是 `joint_T_limit = 25`
留给跳跃/落地冲击的余量来源。

**教训：判断弹簧太硬/太软之前，先确认力需求那一侧的数字可信。**

几何已由三组 CAD 数据交叉验证（`mount_offset` 三点极差 0.0055°、回代残差 0.003 mm）；
行程也已定案（断电腿被顶到 375/371 mm = 机构极限，气弹簧没先到底，两端都不卡）。

**开启前只剩一件事**：`observer` 那组力类比例阈值要在正确标度下重标
（`Observer_Static_Load()` 已从 54.3 变成 102.0 N）。

## 6. 自起：那一蹬是几何必然，不是 bug

两腿分居大地竖直两侧时（实测 `phi0 = 0.9` 与 `3.14`），SWING 要求两腿 `theta` 都进同号
窗口，**必然有一条腿穿过 `theta = 0`**，穿过时腿在 `extend_L0 = 0.35` 最长态、轮子踩地。
它只随 `theta_b` 换腿，不会消失。嫌猛是降 `rotate_rate` 的事。

顺带确认了 `Recovery_Swing` 的卡滞屏障判据**帧不一致**（只看机体系 `phi0`，不看
`theta_b`/`theta_ref`），实测某些工况净负收益。**未修**——气弹簧真开之后姿态分布会变，
届时按台架读数再定。详情记在 `chassis_control.c` 的方向锁注释和
`chassis_config.h` 的 `phi0_barrier` 注释块里。
