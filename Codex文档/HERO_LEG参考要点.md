# HERO_LEG 参考要点

参考工程：`/home/quickq/code/STM32/Others/HERO_LEG`（`Chassis/` 下板 + `Gimbal/` 上板，STM32F4）。

本文只记录**已在源码中亲自核实**的事实，以及本工程的对应结论。两车机械参数、执行器方向、质量和 K 系数都不同，因此只借鉴控制组织方式，不搬阈值、PID 和经验倍率。

## 0. 读 HERO 源码前必看

**源文件是 GBK/ISO-8859 编码。`grep` 会把它们当二进制静默跳过，一行都不输出，看起来就像"这个符号不存在"。**

```bash
grep -an "关键字" 文件            # 必须加 -a
iconv -f GBK -t UTF-8 文件 | less  # 要看中文注释再转码
```

曾因为漏了 `-a` 得出"HERO 里不存在 `Target_L0`"的错误结论。**任何关于 HERO 的结论都要用 `grep -a` 回源码亲自确认**，不要转述二手描述。

## 1. 小陀螺（本工程 `CHASSIS_MODE_TOP` 的参考来源）

| 项 | HERO 做法 | 源码位置 |
|---|---|---|
| 模式载体 | `bool Flag.spinning_flag`，不是枚举 | `Task/Inc/Chassis_Task.h:30` |
| 进入 | `E` 键松开边沿翻转（<500 ms 短按），或拨轮 `ch[4]` 非零 | `Task/Src/Chassis_Task.c:427-454` / `:734-736` |
| 转速 | 按腿长分三档 **11.0 / 9.0 / 6.0 rad/s** | `Parameter_Tree/Parameter.h:24-26` |
| 进控制器 | `u[3] = d_yaw_t − d_yaw` 直接进十维 LQR，**底盘无独立 yaw PID** | `Controller/Src/LQR.c:86` |
| 屏蔽反馈 | `u[0]`(位移) 与 `u[2]`(航向角) **整项乘 0** | `Controller/Src/LQR.c:145-152` |
| 加姿态增益 | 腿摆 θ/θ̇ **×1.2**、机体 pitch **×3.0**、pitch 速率 **×1.4** | 同上 |
| 关打滑检测 | 注释明写"小陀螺时关闭打滑检测" | `Chassis_Task.c:174-178` |
| 关里程计 | `body->x` 硬清零 | `Chassis_Task.c:829-860` |
| 平移 | **强制归零**（`Ramp_Function(0,...)`），是纯原地自转 | `Chassis_Task.c:738/755/787` |
| yaw 反馈 | 用**云台 6020 编码器**，天然在 ±π 内，不需解缠 | `Chassis_Task.c:120` |

**两个容易被误读的点：**

1. HERO 在 `Chassis_Task.c:296-329` 写了一整套 `cos(follow_theta)` 平移解耦，**但小陀螺分支里一次都没读过它**，是死代码。
2. 它靠云台指向解决"哪边是前"，本工程无云台，只能靠进入瞬间锁存的 `top_fai`。

**本工程结论**：已屏蔽 `s/fai`（走 `Chassis_Config.top.scale[]` 配置表，比 HERO 硬编码更通用），**未复制 1.2/3.0/1.4 经验倍率**——那是为 11 rad/s 硬扛离心和陀螺力矩用的，本工程当前 `max_d_fai = 2.0 rad/s`，用不上。真要补偿改配置即可，一行代码不用写。本工程实现了完整二维平移投影并真的接进了 `target[D_S]`，这一点比 HERO 完整。

## 2. 腿长控制（重要：HERO 给不出斜坡参考）

**HERO 对腿长目标没有任何斜坡**，`Target_L0` 是 `DOWN_LEG_LENGTH 0.16` ↔ `MID_LEG_LENGTH 0.25` 的硬阶跃（`Chassis_Task.c:467-468`）。

它变腿长不猛，靠的是本工程**没有**的两样东西：

1. **450 N 气弹簧**（`Parameter.h:6` `FL 450.0f`）扛掉绝大部分静载；
2. `G_Comp` 支撑力前馈 = `1.62 × LPF(实测支撑力 Fn − 气弹簧分量 fl)`，LPF RC 0.05 s。

腿长 PID：`kp=2000, ki=0, kd=130, max_out=180 N`（`PID_Init` 参数顺序为 `max_out, integral_limit, deadband, kp, ki, kd, ...`，别按常见顺序误读）。

**易误认的符号**：`Bring_Legs.Comp_Length` 看着像腿长过渡量，实际是**腿卡住时的提腿补偿**，由 `stuck_time` 驱动（`Chassis_Task.c:890-917`），与腿长变化无关。

**本工程结论**：不引入气弹簧补偿（无此机构）；腿长平顺化改用目标斜坡（`Move_Toward` + `recovery.L0_rate`），这是本工程自己的方案，不是 HERO 的。

## 3. 其他逐项对照

| 项 | HERO 做法 | 本工程结论 |
|---|---|---|
| 轮速估计 | 轮线速度 + `R*d_theta` 定子转动 + 腿摆平动速度相加 | 已补齐 `R*d_theta` 项，并用整车前向加速度作 Kalman 输入 |
| 打滑检测 | 轮速 yaw 残差、轮速与车速残差、轮速增量与 IMU 加速度残差 | 三类残差已引入，加低通、进入/退出持续时间和滞回 |
| 离地检测 | 由虚拟支撑力、腿部加速度和 IMU Z 加速度估算法向力 | 已实现关节力矩→虚拟力逆映射和法向力估计 |
| 爬台阶 | 抬腿接近、轮请求与腿角判碰撞、收腿摆动、碰撞后轮输出清零 | 已实现四阶段状态机，额外加了反馈力矩确认和各阶段超时 |
| 模式增益 | 同一 K 上按模式改反馈项 | 用统一 K 点乘 + `lqr.scale[]` 状态缩放，不引入未经本车模型验证的独立 K |
| 气弹簧 | 按原车几何算支撑力前馈 | 无此机构，不引入 |

**F0 符号约定相反**：HERO 用 `F0 < 0` 撑地，本工程 `F0 > 0` 撑地（已由虚功数值验证）。搬 HERO 公式时符号必须翻。

## 4. HERO 中发现、本工程未照搬的问题

1. 1 kHz 任务里位移积分用固定 `0.01 s`，与实际周期不符。
2. 两处模式条件重复检查左侧打滑标志，漏掉右侧。
3. 台阶动作无阶段超时，传感条件不满足时可能永久停留。
4. 部分 VMC 开方和除法缺输入有效性处理。
5. 小陀螺姿态增益倍率、离地阈值、碰撞阈值全部绑定原车参数。
6. 两块板的云台零点常数不一致：底盘 `ZERO_HEAD_YAW = 0.14728014`（`Parameter.h:14`），云台 `0.214783534`（`Gimbal/Task/Inc/Gimbal_Task.h:22`），差 0.0675 rad ≈ 3.9°。
