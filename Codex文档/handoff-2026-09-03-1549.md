### 3.1 ⚠ 有一个用户提问**没有回答**（本轮最高优先级）

用户最后一句：**「转腿方向反了，倒地自起转腿有点舍近求远，应该怎么改？」** —— 我尚未作答，请从这里继续。

已定位到相关代码（`chassis_control.c: Chassis_Recovery()` 的 FALLEN 分支）：

- `:879` `theta_ref = (theta_min + theta_max) * 0.5f` → 当前 = **+0.95 rad 单边正值**
- `:881-886` 用 `theta_ref` 作参考取 `Algorithm_AngleNearestEquivalentRad` 的等价角
- `:909-910` 判据 `theta >= theta_min && theta <= theta_max`，窗口 `[0.50, 1.40]` **同样是单边正的**
- `:913-914` `direction = (theta_b < 0.0f) ? 1.0f : -1.0f;`（上面还有一行被注释掉的同样内容，用户动过）
- `:947-951` `target_phi0 += direction * rotate_rate * dt` 单调推进，**不判断当前 theta 离窗口哪一侧更近**

**初步假设（未验证，交给下一个 agent 确认）**：theta 窗口和 `theta_ref` 都只描述了**一个倒地方向**。车往另一侧倒时，等价角会被归到远端、窗口也要求转到正的一侧，于是必须绕远路——这正好同时解释「方向反」和「舍近求远」两个症状。

**可能的改法方向**（需与用户确认约定后再动手）：
- 让窗口对称：判据改用 `|theta|` 落在 `[theta_min, theta_max]`，`theta_ref` 的符号由倒地方向决定（如 `copysignf(theta_ref, -theta_b)`）
- 或：`direction` 不再只看 pitch 符号，改为看当前 theta 离窗口哪一侧近
- ⚠ 这属于**算法语义变更**，按 `CLAUDE.md` 的红线（"算法代码只去封装，不改数学"）必须先跟用户对齐意图，不要自作主张改公式
