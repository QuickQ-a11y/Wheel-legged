## 1. 背景与目标

倒地自起的最后两个阶段（摆腿 Swing / 收腿站起 DrawBack）原先都用"最短弧/就近原则"
选转向，实机发现某些起始腿角的近路会**把腿怼进地里卡住**。本轮把两个阶段的转向
判据都改成**避开卡滞屏障**。

## 2. 已完成工作

### 核心概念：卡滞屏障

新增 `Chassis_Config.recovery.phi0_barrier = 0.4f`（主值 `phi0` 口径），
含义是**腿不许跨过的角度**。摆腿和收腿共用，是机构属性不是阶段属性。

- **DrawBack**：把圆在屏障处剪开展成 `[0,2pi)`，在展开坐标里直着走到 `bench_phi0`
  ```
  u        = fmodf(phi0       - barrier + 2pi, 2pi)
  u_target = fmodf(bench_phi0 - barrier + 2pi, 2pi)   /* = 1.1708 */
  行程      = u_target - u                             /* 符号即转向 */
  ```
  目标在 `State_Enter(CHASSIS_FALLING_TO_STAND)` 按腿锁存到 `drawback_goal_phi0[]`，
  **不能每拍重算**——屏障是不连续点，重算会让腿在那儿掉头撞进卡滞区。
- **Swing**：屏障下侧强制反转（从机体正上方绕），上侧沿用原就近原则。
  全周扫掠验证过上侧的近路不会跨屏障，所以那一侧不必改。

具体代码和注释见 `chassis_control.c` 的 `State_Enter` / `Recovery_Swing` /
`Recovery_Drawback`，以及 `chassis_config.h` 的 `phi0_barrier` 注释块。

## 6. 关键上下文

### 两个阶段的分工（本轮反复搞混过，写清楚）

| | Swing 摆腿 | DrawBack 收腿站起 |
|---|---|---|
| 状态 | `CHASSIS_FALLEN` 第二子阶段 | `CHASSIS_FALLING_TO_STAND` |
| 腿长 | 伸到最长 0.35 | 收到最短 0.15 |
| 腿角目标 | 起立预备角（`theta` 窗口 0.50~1.40） | 竖直向下 `bench_phi0`=1.5708 |
| 角度口径 | `theta`（世界系，含机体俯仰） | `phi0`（机体系） |

**DrawBack 入口可达集合 = `[0.17, 1.07] ∪ [1.15, 2.97]`**
（摆腿 theta 窗口换算 ∪ 跳过捷径的 `phi0_min/max`）。
排查"某个腿角为什么这样转"时先用这个集合判断到底是哪个阶段在转——
本轮就因为没先做这一步而改错了两次函数。

### 已知后果（用户知情、刻意保留）

Swing 窗口 `phi0 ∈ [0.17,1.07]` 与屏障下侧 `[0.17,0.4)` 重叠，所以 Swing 可能
正常结束在屏障下侧，随后 DrawBack 再绕 4.8 rad。最坏叠加 ≈ 4.75 s，在
`fallen_timeout 8.0` / `prepare_timeout 6.0` 之内。嫌慢就提 `drawback_phi0_rate`
（现 1.50，ZJU 用 3.49）或收紧 `theta_max`。
