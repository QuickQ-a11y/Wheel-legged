## 2. 结构：两层正交状态机

```
拨弹   IDLE ──进使能区(同拍加一发)──→ HOLD ──保持超 BURST_DELAY──→ BURST
        ↑                              │                              │
        └──────── 松开 ────────────────┴──────────────────────────────┘

防卡弹 NORMAL ──堵转码‖电流饱和──→ SUSPECT ──持续 jam_confirm_s──→ BACKING
         ↑                           │(判据消失)                      │
         └───────────────────────────┘                    ┌───────────┴───────────┐
                                              retry < max │                       │ retry ≥ max
                                                      NORMAL                   GIVEUP
                                                                                  │松开 VrB
                                                                               NORMAL
```

⚠⚠ **两层靠 `Shooter_Control` 里那一个 `if` 正交**：只有 `NORMAL`/`SUSPECT` 才跑
拨弹逻辑，`BACKING`/`GIVEUP` 期间**整个旁路**。否则退弹的目标角会被下一轮加发覆盖。
抄自 RoboWalker `crt_booster.cpp:155`。删掉它 `test_shooter` 会红。

### "那一发"没有单独的状态

它发生在 `IDLE -> HOLD` 的**转移**上。一次进使能区只转移一次，所以
"一次进入 = 一发"天然成立，**不需要在遥控层做边沿检测**。
RoboWalker 用的是"执行完立刻把状态自己改回 CEASEFIRE"（`crt_booster.cpp:222`），
同一个思路，我们这边连那个瞬态都省了。

### 相对参考实现修掉的一个缺陷

⚠ **目标角从"上一次目标"累加，不是从当前反馈角累加。**
RoboWalker `crt_booster.cpp:217` 是 `Get_Now_Angle() + 2π/7`——上一发还没转到位就来
第二发时，新目标基于**半途角**，这一发就短一截。连发、以及卡弹退弹刚结束时必然踩到。
`test_shooter` 的 `testTargetAccumulatesFromTargetNotFeedback` 专门钉死这条：
让拨盘纹丝不动连打 1 秒，从目标累加得约 9 发，从反馈累加永远只有 1 发。

### 参考的两个工程都没有的一层：放弃

RoboWalker 的四态是**死循环**，可以永远"退一点、再顶、再退"；SPR 作者自己在
`shoot_task.c:348` 注释里点了同一个问题（「循环多次自动关掉电机防止电机烧坏」）。
这里加了 `jam_retry`：连续 `jam_retry_max`(3) 次退弹仍未脱困 → `GIVEUP`，
拨盘零输出，**唯一出口是松开 VrB**（堵转消失本身解不开，否则会无限自动重试）。

⚠⚠ **`GIVEUP` 故意不置 fault 位。** `fault` 会经 `safe_flag` 把**四台电机全部清零**——
拨盘卡死时摩擦轮应该继续转，脱困后要能立刻接着打。放弃这件事由 `Shooter.jam_state`
本身表示，不另存一份（同一份事实只保留一个所有者）。
`testGiveUpAfterRetries` 里有一条断言钉死"此时摩擦轮仍在出力"。

## 3. ⚠⚠ 模块内有两套单位口径，这是有意的

| | 摩擦轮（减速箱**已拆**，1:1） | 拨盘（减速箱**还在**，36:1） |
|---|---|---|
| 速度 | **rpm**，`speedRpm` 直接就是轮速 | **输出轴 rad/s**，要除 36 |
| 位置 | — | **输出轴 rad** |

⚠⚠ **三个摩擦轮的 P36 减速箱是物理拆掉的**（2026-09-25 确认），所以它们的
`speedRpm` 就是轮子转速，**不要再除 36**；拨盘的减速箱还在。
四台电机减速比不同，对应关系只在 `device_motor_dji.c` 的 `djiGearRatio[]` 里写一次。
拨盘算错这个数"一发"就差 36 倍，摩擦轮算错则是速度环量纲整体偏 36 倍。

拨盘换到输出轴，是因为**一发 = 2π/N 这个关系只在输出轴上成立**，调参时也只有
输出轴角度可想象。摩擦轮那套沿用现状不动。

- `motor_dji_state_t.angle` 是设备层算好的输出轴弧度（按 `djiGearRatio[]` **逐台**除）
- 角速度是 `speedRpm` 的纯换算、无状态，所以在 `shooter_control.c` 用的地方直接算，
  没往设备层加字段

⚠ 设备层新增的编码器回绕累加（`device_motor_dji.c`，抄自 `dvc_motor_dji.cpp:973-987`）
里有一个坑：**首帧不能判回绕**。`lastEncoderRaw` 上电是 0，第一帧算出来的 delta 是假的，
所以只有 `isOnline != 0` 之后才判。`test_motor_dji` 的 `testEncoderWrap` 必须排在
`main()` 的**最前面**——设备层状态是静态的，别的用例先把这台电机带上线就验不了首帧了。

## 4. 实现时发现的一个真 bug（单测撞出来的，不是事后想到的）

待发状态（`IDLE`）原先只在**进入那一拍**清 PID 积分。
误差为 0 时积分**不会自己衰减**，于是上一轮留下的积分会让拨盘在待发状态
**一直带着小电流**。改成逐拍清。

这条是写 `testCascadeDrivesTowardTarget` 时，"待发状态 `I_req` 应该是 0" 这条断言
在真实运行里挂掉才发现的。

## 5. 任务拆分

发射机构从 `gimbal_task` 里拆出来，新建 `shooter_task`，1 kHz，
**与云台同为 `osPriorityHigh`**，各自 `osDelayUntil` 独立相位、各自测自己的 `dt`。

⚠ **拆得动的前提是两边没有共享状态**：云台只碰 `Motor_DM`、发射机构只碰 `Motor_DJI`
（两边互相引用次数为 0），而 CAN 发送缓存由 `task_can` 的 `canTxMutex` 保护。
**再往任一模块里引入对方的设备层之前，先想清楚这条还成不成立。**

⚠ 优先级给同级而不是低一级：低一级会被 `osPriorityAboveNormal` 的遥控/USB 任务抢占，
而拨盘位置环对周期抖动比速度环敏感。

⚠ 两个任务各自读全局 `Remote`（`task_remote.c` 只在写侧加锁），所以云台和发射机构
**可能看到相邻两帧的遥控值**。现在不构成问题——云台用 SwC/右摇杆/SwD，发射用 VrB，
互相独立。将来若出现两者必须看同一帧的语义，这里要先加同步。

⚠ 新任务栈给了 `1024 * 4`（4 KB），**是按"Debug 构建栈用量明显更大"留的余量，不是实测值**。
实机用 `rtosStackOverflowTaskName`（`freertos.c:150` 的钩子）核对。

## 6. 验证

| 项 | 状态 |
|---|---|
| 云台三后端各 `--clean-first` | ✅ DR16 / IBUS / SBUS 各 0 警告 0 错误，宏留在 SBUS |
| 主机单测 9 次运行 | ✅ 全过（`test_shooter` 跑两遍，见下） |
| 变异验证 27 个 | ✅ 全部被抓住 |
| **实机** | ❌ **一次都没上** |

⚠⚠ **`test_shooter` 必须跑两遍**，第二遍加 `-DAPP_SHOOT_TRIGGER_DIR=(-1.0f)`。
默认 `DIR` 是 `+1`，此时"代码乘了这个常量"和"压根没乘"**在数学上完全一样**，
单跑默认那遍查不出漏乘——实测确认：漏乘这个变异只有在 `-1` 那遍才被抓住。
而实机上把宏翻成 -1 却毫无反应会非常难查。`app_config.h` 里那个 `#ifndef`
就是为这件事留的，**别顺手删掉**。

⚠ 写用例过程中有 **4 个变异一开始没被抓住**，值得记下来都是什么洞：

1. **观察窗口太短**——验"卡弹期间拨弹被旁路"时只看了 50 ms，而连发节拍是 125 ms，
   旁路删掉了也看不出来。窗口要**夹在**"一个连发节拍"和"退弹时长"之间，两边都卡死。
2. **拨盘在测试里从没真转过**——`speedRpm` 恒为 0、编码器恒为 0，于是
   "角速度漏除减速比"和"反馈角没取设备层的 angle"两个变异全都活着。
   补了 `advanceTrigger()` 让拨盘真转起来才堵上。
3. **dt 正好整除节拍**——实机 1 kHz / 8 Hz = 125 拍整，此时"减去一个周期"和"清零"
   结果完全一样。补了一条故意用粗 dt（25 Hz）的用例。
4. **断言写成了死代码**——GIVEUP 里那句 `I_req[TRIGGER] = 0` 其实是冗余的
   （函数开头 `memset` 已经清过），删掉没有任何用例会红，所以把它删了。

## 7. 还欠什么

### ⚠⚠ 占位值，一个都没有实机依据

| 常量 | 当前值 | 怎么定 |
|---|---|---|
| `APP_SHOOT_AMMO_PER_ROUND` | **8** | 数拨叉槽位 |
| `APP_SHOOT_TRIGGER_DIR` | **+1.0f** | 拨盘**不装弹**空转，VrB 进使能区打单发看转向 |
| `trigger_angle_pid` / `trigger_speed_pid` | 量纲推算值 | 实机整定 |
| `jam_current` / `jam_confirm_s` / `jam_back_s` / `jam_back_rad` / `jam_retry_max` | 抄 RoboWalker 的比例 | 手动顶住拨盘实测 |
| `fric_default_rpm` | **5000** rpm（减速箱已拆，即轮速） | 实机整定 |

（原先这里记着"5000 转子 rpm 只等于输出轴 139 rpm，量级可疑"——
2026-09-25 确认**摩擦轮的减速箱是拆掉的**，所以 5000 直接就是轮速，
量级上对得起 17mm 摩擦轮。仍需实机整定。）

### 实机三步走（`handoff-2026-09-24-0740.md §7` 那三步仍然有效，外加）

4. 拨盘**不装弹**空转：VrB 进使能区打单发，核对转向、核对"一发"的角度对不对，
   再装弹。装弹之后才测方向的话，方向反了会把弹往回拨。
5. 手动顶住拨盘，读 `Shooter.motor[3].errorCode` 变 6 的**延迟**和
   `Shooter.motor[3].currentRaw` 的**稳态值**，回填 `jam_confirm_s` / `jam_current`。
   ⚠ 堵转码的响应延迟和灵敏度**手册没写**，这是现在拿电流饱和做第二判据的原因。

### 继承的

6. 云台 `APP_DM_TOR ±10` 仍未与 DM4310 的 TMAX 寄存器核对。
7. `APP_RC_LEG_CROUCH` 等于行驶腿长，"压缩腿"实际不压。
8. S.BUS 的模式与 failsafe 行为还没实机跑。
9. 跳跃、自瞄仍只有名字。

### 明确不做

- **热量与火控**：没有裁判系统，热量没有真值。SPR 试过用摩擦轮力矩方差估热量，
  三轮全失败（代码全注释），而我们**三个摩擦轮**做不了他们那种左右对称消扰。
  连发射频就用 `APP_SHOOT_BURST_HZ` 常量。
- **"这一发是否真打出去了"的检测**：SPR 废弃、RoboWalker 根本没做。位置环转到位就算一发。
