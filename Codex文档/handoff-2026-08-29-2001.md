## 2. 已完成工作

### 2.1 小陀螺（TOP 模式）接通

TOP 链路本来就已实现约 90%（模式枚举、二维平移投影、`top.scale[]` 屏蔽位移/航向位置反馈、
打滑观测器 TOP 门控）。缺的只是拨杆映射。

- `remote_input.h:32` — `REMOTE_MAP_LEFT_MID` 由 `FOLLOW` 改为 `REMOTE_MODE_TOP`
- `chassis_config.h` 的 `Chassis_Top_Config_t` 新增 `d_fai_rate`；两个 `.top` 块各加 `.d_fai_rate = 3.0f`
- `chassis_control.c` 的 `Motion_Update` TOP 分支 —— `target[D_FAI]` 改为 `Move_Toward()` 限速逼近

拨杆现状：右下=急停、右中=零力、右上+左上=跟随、右上+左中=**小陀螺**、右上+左下=自救。
`max_d_fai = 2.0 rad/s`（保守，先验证链路），`max_d_s = 0.25 m/s`。

### 2.2 腿长目标斜坡恢复

`chassis_control.c` 的 `Motion_Update` 末尾，恢复被注释掉的 `Move_Toward` 斜坡，
速率取 `Chassis_Config.recovery.L0_rate`。

**根因（关键，勿丢）**：`State_Enter(CHASSIS_STANDING)` 已把 `target_L0` 软接管到当前实际腿长，
但 `Motion_Update` 下一拍用 `target_L0 = goal.L0` 把接管抹掉。自救结束腿停在 `bench_L0`，
一拍被拽到 `goal.L0`；收腿方向与重力同向、腿长 PID 仅 `kd` 一项阻尼 —— 这就是用户反馈的
"伸腿后又收腿那一下"。

### 2.3 F0 共模/差模解耦（本轮最重要的控制改动）

`chassis_control.c` 的 F0 装配，从「每腿一个腿长 PID + 横滚差动」改为：

```
共模 H = (L0_L + L0_R)/2   -> 腿长 PID（车身高度）
差模                       -> 横滚 PID（IMU roll 反馈）

F0_L = height_force + roll_force - gravity_L + F0_left
F0_R = height_force - roll_force - gravity_R - F0_right
```

**为什么必须改**：横滚控制靠制造左右腿长差来纠正车身，而两条腿共享同一个 `target_L0`，
腿长 PID 一见到腿长差就反向拉回。两个环在差模上直接对抗，**且与增益大小无关**。
改成共模后腿长 PID 不再看见腿长差。

参考工程 Qi-Q26 的作者独立得出同一结论（见 `Qi-Q26方案分析与TinyMPC可行性.md`）。

配套：`Chassis.leg_length_pid` 由每腿一份改成共模一份（`chassis_control.h`），
三处复位点各由两次调用合成一次，测试里两处数组下标去掉。

安全性已排查：**没有任何用到 F0 的状态依赖腿长 PID 产生差动力**
（STANDING/STEP 左右 `target_L0` 相同；BENCH 的 F0 强制为 0；自救走关节串级不算 F0）。

**MATLAB 与固件的活动配置块参数完全不一致。**

`Matlab/ABK_LQR.m` 中当前**未被注释**的那组是**小轮腿**的值，而固件编译的是 `BIG_WHEEL_LEG`：

| 参数 | MATLAB | 固件 BIG 块 |
|---|---|---|
| `R_w_ac` / `wheel.R` | 0.052 | 0.058 |
| `l_c_ac` / `cg_to_hip` | 0.060 | 0.120 |
| `m_b_ac` / `body_mass` | 3.043 | 12.0 |
| `m_l_ac` / `leg_mass` | 1.054 | 1.65 |
| `m_w_ac` / `wheel_mass` | 0.455 | 0.537 |

固件 `lqr.L0_min/L0_max = 0.10/0.30`。

**无法从代码判断现在贴着的 K 是哪次跑出来的**，但可以确定：照原样重跑 `ABK_LQR.m`，
得到的 K 不属于固件正在配置的这台车。

### 6.3 读参考工程的陷阱

**HERO_LEG 源码是 GBK/ISO-8859 编码，`grep` 会当二进制静默跳过、一行不输出**，
必须 `grep -a`，看中文再 `iconv -f GBK -t UTF-8`。本轮曾因此得出错误结论。

**不要全盘相信子代理对参考工程的转述** —— 本轮子代理报告的变量名就是错的，
涉及参考工程的结论都要回源码用 `grep -a` 亲自确认。
