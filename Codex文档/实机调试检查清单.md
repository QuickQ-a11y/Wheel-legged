# 轮腿底盘实机调试检查清单

本文档用于轮腿底盘首次上电、机构标定、低力矩测试和闭环调试。调试时按顺序执行，不要跳过机械参数、传感器和安全输出检查。

## 0. Watch 窗口分组

`Chassis` 全局约有 340 个可观测标量，一次全加进 Watch 既看不过来，也会明显拖慢刷新率。
Watch 只采样手动添加的条目，按下面分组按需添加，不要展开整个结构体。

**A 组 常驻（8 条）**

| 变量 | 看什么 |
|---|---|
| `Chassis.fault` | 第一个要看的，非零就不会有输出。位定义见 `chassis_control.h` |
| `Chassis.state` / `Chassis.mode` | 内部状态机与外部请求模式 |
| `Chassis.output.safe_flag` | 置位表示最终命令被清零 |
| `Chassis.dt` | 越界会回退，异常说明任务调度有问题 |
| `Chassis.leg[0].valid_flag` / `[1]` | 五连杆本轮是否有数学解 |
| `Chassis.dm_motor[0].err_state` | DM 反馈状态位，`0`失能 `1`使能 `8~E`错误 |

**B 组 站立与平衡** —— `Chassis.lqr.x`、`Chassis.lqr.target`、`Chassis.lqr.error`（三个数组各占一条），
`Chassis.leg[0/1]` 的 `L0`、`theta`、`F0`、`Tp`。
`lqr.error` 是限幅后真正进 K 点乘的量，某一路输出被单个状态主导时先看它。

**C 组 输出链路** —— `Chassis.output` 的 `T_wheel`、`T_joint_req`、`T_joint`、`I_wheel`，以及 `Chassis.imu.pitch`。
`_req` 是请求量、无后缀是过完安全门的实际命令，两者不等即被门拦下。

**D 组 关节校零** —— `Chassis.leg[0/1]` 的 `phi1`、`phi4`、`phi0_total`，`Chassis.dm_motor[0..3].position_rad`。
判据：腿竖直向下时 `phi1 + phi4 = pi`，且同一条腿两个电机读数等值反号。

**E 组 速度融合** —— `Chassis.body` 的 `d_s_raw`、`d_s`、`dd_s`、`dd_s_fused`。

**平时不要展开的**

- `Chassis.slip` / `ground` / `turn` / `stuck` —— 四套只读观测约 91 个标量，不参与控制，基础调试用不到。
- `Chassis.speed_kalman` 和六组 PID state —— 约 60 个滤波器内部状态。
- K 矩阵不在 `Chassis` 里，它是 `chassis_control.c` 的文件静态量 `lqrK`，每周期由 `leg[].L0` 重算；
  需要时直接观察该静态量，或看 `Chassis.leg[].K_L0_fit` 和 `Chassis.lqr.limit_flag` 判断拟合输入是否被夹紧。

## 0.5 遥控拨杆分配

右拨杆管「允不允许动」，左拨杆管「动起来做什么」。

| 右拨杆 | 语义 | 行为 |
|---|---|---|
| 下 | 急停 | 输出立即封锁，解除武装（`remote_stop_flag = 1`） |
| 中 | 零力矩待命 | 电机全软，可搬运摆姿态；不解除武装 |
| 上 | 运行 | 左拨杆的模式生效 |

| 左拨杆（仅右拨杆在「上」时生效） | 模式 |
|---|---|
| 上 | `FOLLOW` 站立平衡、遥控移动转向 |
| 中 | 同「上」，位置留给以后的 TOP / STEP |
| 下 | `SELF_SAVE` 倒地自救 |

摇杆与拨轮：左摇杆 Y = 前进速度，右摇杆 X = 偏航角速度，拨轮 = 三档腿长。

**重排拨杆只改 `remote_input.h` 里这四行宏**，不要动 `device_dr16.c`：

```c
#define REMOTE_MAP_RIGHT_MID  REMOTE_MODE_ZERO_FORCE
#define REMOTE_MAP_LEFT_UP    REMOTE_MODE_FOLLOW
#define REMOTE_MAP_LEFT_MID   REMOTE_MODE_FOLLOW
#define REMOTE_MAP_LEFT_DOWN  REMOTE_MODE_SELF_SAVE
```

可填任意 `REMOTE_MODE_*`（含 `BENCH` / `TOP` / `STEP`，这三个模式的控制代码都还在）。

**右中是万能出口**：`chassis_control.c:446-452` 给 `CHASSIS_MODE_ZERO_FORCE` 最高优先级，会同步 `last_mode` 并清 `fault`。任何卡死状态下拨到右中都能把车拉回零力矩。开机建议停在右中。

## 1. 当前安全状态

当前非零输出由五类条件共同控制：

1. `app_config.h` 中的 `APP_CHASSIS_OUTPUT_ENABLE`。
2. `chassis_config.c` 中的 `output.joint_flag` 和 `output.wheel_flag`。
3. `Chassis.enable_flag` 开放底盘非零输出许可。
4. IMU、DM、DJI和CAN通信正常。
5. 关节力矩、轮力矩、电流换算和电流限幅必须为有效非零值。

默认配置仍保持安全零输出。调试时不要一次打开全部条件，应先测试单类电机，并使用很小的力矩或电流限幅。

## 2. 闭环前必须确认

### 2.1 关节机械零位

`angle_offset_rad` 必须让实际机构姿态与 `phi1/phi4` 的模型定义对应。

手动摆动腿部，观察：

```text
Chassis.leg[0]    左腿
Chassis.leg[1]    右腿
```

左右腿处于机械对称姿态时，应满足：

- 左右 `L0` 基本一致。
- 左右 `phi0` 基本一致。
- 缓慢跨越正负 pi 时，`phi0_total` 连续且增量方向正确。
- `phi1/phi4` 主动杆角符合实际姿态，左右镜像时对应角基本一致。
- 缓慢停止后，腿长速度和腿角速度回到接近 0。

零位错误应修改 `angle_offset_rad`，不能通过 `scale` 补偿。

### 2.2 五连杆机械参数

核对 `chassis_config.c` 中：

```text
l1
l2
l3
l4
l5
```

`l5` 表示两根主动杆输出铰点之间的距离，不是两个 DM 电机轴之间的物理距离。本车通过同步带把两个电机分别连接到重合的主动杆输出轴，因此当前 `l5 = 0.0f` 正确；机构改变后必须重新测量输出铰点间距。

还需要确认：

- 当前五连杆交点分支与实机腿部构型一致。
- 正常工作区不会越过机构死点。
- `sin(phi2_rad - phi3_rad)` 不会接近 0。
- 实际腿长保持在允许范围内。

### 2.3 轮半径与模型一致性

当前固件配置：

```text
Chassis_Config.wheel.R（轮半径，实机整定期数值以源码为准）
```

当前 `ABK_LQR.m` 使用：

```text
R_w_ac = 0.155 / 2 = 0.0775m
```

两者不一致会影响轮速换算、`dot_s` 状态和 LQR 模型。闭环前必须确认实际有效轮半径，并统一 MATLAB 与固件参数。

### 2.4 控制周期

底盘任务目标周期为 `1ms`。每周期由 RTOS tick 计算 `Chassis.dt`；超出配置范围时回退到 `Chassis_Config.default_dt = 0.001s`。PID、Kalman、位移积分和状态机统一消费该周期。

这会影响：

- PID 积分速度。
- Kalman 状态转移。
- 前进位移积分。
- 腿长和腿角速度相关计算的时间尺度。

正式闭环前应在运行中观察 `Chassis.dt`，确认其稳定在约 `0.001s`，且不存在持续回退或明显抖动。

### 2.5 K 拟合范围

当前 K 系数的实际采样范围和固件输入限幅均为：

```text
0.12m ~ 0.31m
```

恢复和台阶配置仍声明目标机械工作区：

```text
0.15m ~ 0.29m
```

当前连杆理论最大腿长约为 `0.296m`，恢复和台阶最大目标限制为 `0.29m`；现有 K 采样上限 `0.31m` 已覆盖该机械范围。改变连杆或扩大闭环腿长范围前，仍应使用实测整车参数重新生成并验证 K。

## 3. IMU 检查

整车业务层使用右手系：

| 坐标轴 | 正方向 | 对应线加速度 |
|---|---|---|
| `+X` | 车头前方 | `Chassis.imu.body_accel[0] > 0` 表示向前加速 |
| `+Y` | 车体左方 | `Chassis.imu.body_accel[1] > 0` 表示向左加速 |
| `+Z` | 车体上方 | `Chassis.imu.body_accel[2] > 0` 表示向上加速 |

欧拉角和角速度均遵循右手定则，当前代码采用标准 ZYX 欧拉角表达：

| 角度 | 旋转轴 | 正方向对应的实际动作 | 对应角速度 |
|---|---|---|---|
| `roll > 0` | `+X` | 左侧车身升高、右侧降低 | `Chassis.imu.gyro[0] > 0` |
| `pitch > 0` | `+Y` | 车头降低、车尾升高 | `Chassis.imu.gyro[1] > 0` |
| `yaw > 0` | `+Z` | 俯视逆时针旋转，即车辆左转 | `Chassis.imu.gyro[2] > 0` |

`roll` 和 `yaw` 主值位于约 `[-pi, pi]`，`pitch` 位于约 `[-pi/2, pi/2]`。`Chassis.imu.yaw_total` 与 `yaw` 正方向相同，但跨越 `+pi/-pi` 后连续计圈。以上定义针对经过坐标转换的 `Chassis.imu`，不要使用 BMI088 原始传感器轴直接判断整车方向。

静止水平放置时检查：

```text
Chassis.imu.roll
Chassis.imu.pitch
Chassis.imu.yaw
Chassis.imu.gyro[0..2]
Chassis.imu.body_accel[0..2]
```

预期结果：

- `Chassis.imu.roll` 和 `Chassis.imu.pitch` 接近 0。
- 三轴角速度接近 0。
- 去重力后的运动加速度接近 0。
- IMU 静止时没有明显突跳。

方向检查：

1. 抬高车体左侧并保持车头、车尾高度不变，`roll` 应变为正；抬高右侧时应变为负。
2. 压低车头时 `pitch` 应变为正；抬高车头时应变为负。
3. 俯视车辆向左转时，`yaw`、`yaw_total` 的增量和 `gyro[2]` 应为正；向右转时应为负。
4. 动作停止后，对应角速度应回到接近 0，角度不应出现符号反跳。

当前 yaw 没有磁力计或外部航向观测，会发生长期漂移。K 中 yaw 增益较大，启用控制时必须保证目标 yaw 与当前 yaw 对齐，避免瞬间产生较大转向力矩。

## 4. CAN 与设备状态

### 4.1 电机与 CAN 映射

| 电机 | 数组下标 | 总线 | 命令 ID | 反馈CAN ID | `D[0]`电机ID |
|---|---:|---|---:|---:|---:|
| 左前髋 | 0 | FDCAN1 | `0x004` | `0x014` | `0x4` |
| 左后髋 | 1 | FDCAN1 | `0x003` | `0x013` | `0x3` |
| 右前髋 | 2 | FDCAN2 | `0x001` | `0x011` | `0x1` |
| 右后髋 | 3 | FDCAN2 | `0x002` | `0x012` | `0x2` |
| 左轮 | 0 | FDCAN2 | `0x200` 字节 0~1 | `0x201` | - |
| 右轮 | 1 | FDCAN2 | `0x200` 字节 2~3 | `0x202` | - |

左侧两台DM在FDCAN1，右侧两台DM与两台DJI共用FDCAN2，ID互不冲突。四台DM分别使用独立反馈ID，设备层按`(总线, 反馈ID)`查表匹配，再校验`D[0]`低四位是否等于对应控制ID。DM MIT控制帧与反馈帧的16位位置字段均按电机设定值`-12.5~+12.5rad`映射。速度和力矩字段按当前J4310配置`VMAX=30rad/s`、`TMAX=10N*m`，这三个值必须与电机调试助手里烧写的`PMAX/VMAX/TMAX`寄存器一致。

`D[0]`高四位为DM状态位：`0`失能、`1`使能、`8`超压、`9`欠压、`A`过流、`B`MOS过温、`C`线圈过温、`D`通讯丢失、`E`过载。该值经`Chassis.dm_motor[i].err_state`上送，大于等于`8`时置位`CHASSIS_FAULT_DM_ERROR`（`0x400`）。电机报错后会自行退出使能但仍在发反馈帧，只看`online_flag`会漏掉这类静默失效。

### 4.2 在线状态

在 Watch 中观察：

```text
Chassis.dm_motor[0..3].online_flag
Chassis.wheel_motor[0..1].online_flag
Chassis.can_error_count
Chassis.fault
Chassis.leg[0..1].valid_flag
```

要求：

- 六个电机在线状态持续为 1。
- 手动转动一个电机时，只有对应数组项发生变化。
- 反馈位置、速度和力矩没有异常跳变。
- 正常五连杆状态下，两侧 `valid_flag == 1`；该标志只表示本轮几何状态有数学定义。
- 输出调试前必须满足 `Chassis.fault == CHASSIS_FAULT_NONE`。安全调试期间允许设备故障存在；可定义的几何量和控制请求继续更新，但最终命令保持为 0。

当前CAN发送不重发。底盘任务上电后自动请求DM协议使能；如果漏掉该特殊帧，可能没有进入MIT模式，需要观察DM状态并重新请求协议使能。该使能只用于反馈和MIT通信，`dmSafe`仍保持零力矩保护。

## 5. 电机零位与极性

### 5.1 VMC 侧视坐标和几何角正方向

五连杆在侧视平面内计算，角度方向使用车体轴定义，不能脱离观察侧单独描述顺逆时针：

- 原点位于两个主动杆输出铰点的中点；当前两点重合。
- 平面横轴为整车 `+X`（向车头），纵轴为整车 `-Z`（向下）；`atan2(-Z, +X)` 的正方向等于绕车体 `+Y` 旋转。
- `phi1` 输出铰点位于图右，坐标为 `x = -l5/2`；`phi4` 输出铰点位于图左，坐标为 `x = +l5/2`。
- 后传动杆对应 `phi1`，前传动杆对应 `phi4`；`phi0/phi1/phi4` 均绕车体 `+Y` 增大。
- 从车辆左侧观察时 `+Y` 指向观察者，主动杆逆时针旋转使角度增大；从右侧观察时 `+Y` 指向屏幕内部，主动杆逆时针旋转使角度减小。
- 四个电机均在对应主动杆竖直向下时设置电气零点，此时 `phi1/phi4=pi/2`。
- 左右腿处于镜像姿态时，`phi1`、`phi4` 和 `phi0` 的对应数值应分别基本一致。
- `phi0` 是当前正运动学得到的虚拟腿角，虚拟腿竖直指向地面时 `phi0=pi/2`。
- 当前装配分支的常见展开姿态为 `phi1` 接近 `pi`、`phi4` 接近 `0`；连续角可能选择等价的 `-pi` 分支，因此不使用裸数值大小关系作为保护条件。

本车前髋电机控制前传动杆 `phi4`，后髋电机控制后传动杆 `phi1`。电机与主动杆通过不交叉同步带同向传动，电机带轮与主动杆带轮齿数比为 `3:4`。左右腿使用同一套规范几何定义。上交模型和 HERO_LEG 的角度观察方向及电机公式不能直接复制。

### 5.2 DM 关节电机

DM 设备层只解码和发送 MIT 协议原始坐标。安装镜像方向由 `scale` 处理，主动杆角/电机角传动比由 `ratio=0.75` 处理：

```c
joint_scale = scale * ratio;
phi = angle_offset_rad + joint_scale * motor_position;
d_phi = joint_scale * motor_speed;
motor_torque_command = joint_scale * geometric_torque;
geometric_torque_feedback = motor_torque_feedback / joint_scale;
```

该关系保证电机侧和几何侧的瞬时功率一致：

```text
motor_torque * motor_speed = geometric_torque * d_phi
```

修改规则：

- 反馈角、速度和命令力矩方向不一致时，先检查电机索引、机械映射和测试方法；确认同一关节整体反向后只修改该关节 `scale`。
- 同步带轮齿数改变时修改 `ratio`，不要用 `scale` 补偿传动比。
- 机械零位错误：改 `angle_offset_rad`。
- 电机对应关系错误：改 `motor_index` 或 CAN ID。
- 禁止在 DM 设备层、VMC 公式、PID 或 LQR 增益中临时增加第二个反号。

当前 `Chassis.dm_motor[i]` 保存 DM 原始 MIT 坐标，初始关节配置为：

| 物理电机 | 索引 | 控制ID | 反馈ID | 控制关节 | `offset` | `scale` | `ratio` | 当前几何角公式 |
|---|---:|---:|---:|---|---:|---:|---:|---|
| 左前髋 | 0 | `0x001` | `0x011` | 左腿 `phi4` | `pi/2` | `+1` | `0.75` | `phi4 = pi/2 + 0.75*p_raw` |
| 左后髋 | 1 | `0x002` | `0x012` | 左腿 `phi1` | `pi/2` | `+1` | `0.75` | `phi1 = pi/2 + 0.75*p_raw` |
| 右前髋 | 2 | `0x003` | `0x013` | 右腿 `phi4` | `pi/2` | `-1` | `0.75` | `phi4 = pi/2 - 0.75*p_raw` |
| 右后髋 | 3 | `0x004` | `0x014` | 右腿 `phi1` | `pi/2` | `-1` | `0.75` | `phi1 = pi/2 - 0.75*p_raw` |

四台电机均在对应主动杆竖直向下指向地面时设置电气零点，因此原始位置`p_raw=0`时几何角为`pi/2`。`scale`仍需通过下面的实机步骤确认。

#### 无动力反馈方向检查

保持三层物理输出关闭，逐个缓慢转动关节：

1. 一次只活动一个关节，确认只有对应 `Chassis.dm_motor[i].position_rad` 和对应腿的 `phi1` 或 `phi4` 发生主要变化。
2. 分别确认原始 `position_rad` 与对应 `phi1/phi4` 的关系符合上表；不符合时只修改对应关节的 `scale`。
3. 左右腿做机械镜像的同一动作时，左右 `phi1/phi4/phi0/L0` 应按模型定义对称，不能用原始电机顺逆时针直接比较。
4. 停止运动后 `Chassis.dm_motor[i].speed_radps`、`d_phi0` 和 `d_L0` 应回到接近 0。

#### 极小输出方向检查

该步骤必须在无动力反馈方向和零点确认后进行。架空整车，一次只开放一个 DM，使用极小力矩和短脉冲：

1. 正的原始 DM 力矩命令应使对应原始 `position_rad` 初始增大；若不成立，先检查电机模式、CAN ID 和机械阻力，不能修改 VMC 公式补偿。
2. 正的几何关节力矩应使对应 `phi1/phi4` 初始增大；控制器通过 `scale*ratio` 将其转换为原始 DM 命令。
3. 左侧组合比例为 `+0.75`，所以正几何力矩转换为正原始 DM 力矩；右侧组合比例为 `-0.75`，所以正几何力矩转换为负原始 DM 力矩。
4. 反馈方向正确但输出关系不满足功率共轭时，不允许增加独立的力矩反号，应停止测试并检查反馈、命令或传动映射是否有误。

### 5.3 DJI 轮电机

轮速反馈和轮电流命令方向由同一组配置控制：

```text
Chassis_Config.wheel.left_scale
Chassis_Config.wheel.right_scale
```

轮力矩到电流使用公共绝对换算 `T_to_I`，左右安装方向只由对应 `left_scale/right_scale` 消费一次。反馈方向正确后，再用单轮小电流验证命令方向；若不一致，应检查电机映射和坐标约定，不能在其他位置再叠加一套反号。

轮模型正方向定义为车辆沿整车 `+X` 前进：

- `Chassis.body.wheel_speed[side] > 0` 表示该轮的模型转速推动车辆向前。
- 架空观察正向驱动时，轮胎最低点应向车尾 `-X` 运动；落地后对应地面反力推动车辆向 `+X`。
- 在地面无滑动地向前推动整车时，左右 `Chassis.body.wheel_speed[]` 和 `Chassis.body.side_speed[]` 都应为正。
- 当前 `left_scale=1`、`right_scale=1`，因此代码暂时预期向前滚动时两个 DJI 原始 `speed_rpm` 都为正。该结论必须实机确认，不能依据左右电机外观镜像直接认定。

#### 车轮方向检查

1. 保持轮输出关闭，在地面缓慢向前推动整车，确认左右 `speed_rpm` 分别只进入正确数组项。
2. 确认左右模型 `wheel_speed` 和 `side_speed` 均为正；若某侧为负，只检查该侧电机映射和 `left_scale/right_scale`。
3. 架空并限制极小电流，一次只驱动一个轮；正的最终 `I_wheel[side]` 应使轮胎最低点向车尾运动，同时该侧反馈模型转速变为正。
4. 两轮分别确认后才允许同时输出。两轮正命令必须产生同向前进趋势，不能出现一前一后原地转向。
5. 若某侧反馈和输出同时反向，修改该侧 `left_scale/right_scale`；若只有输出反向，不应立即增加第二套符号，应先核对 DJI 电机、ESC 和 CAN 映射。

## 6. 腿部几何与状态检查

手动缓慢活动腿部，观察：

```text
Chassis.leg[0].phi1
Chassis.leg[0].phi2
Chassis.leg[0].phi3
Chassis.leg[0].phi4
Chassis.leg[0].L0
Chassis.leg[0].phi0
Chassis.leg[0].phi0_total
Chassis.leg[0].d_L0
Chassis.leg[0].d_phi0

Chassis.leg[1]
```

检查要求：

- 实际腿长连续变化，没有跳变或突然清零。
- 腿长应落在 `0.15m ~ 0.29m` 的当前目标工作范围。
- 左右机械对称时，左右腿状态基本对称。
- 静止时速度接近 0。
- 正常工作区不进入几何奇异状态。

如果任一 `valid_flag` 不能置 1，优先检查电机反馈是否为有限值、五连杆交点是否有解以及 `phi2-phi3` 是否接近奇异位置。

## 7. 十维状态与速度融合

状态顺序固定为：

```text
0  s
1  dot_s
2  fai
3  dot_fai
4  theta_l
5  dot_theta_l
6  theta_r
7  dot_theta_r
8  theta_b
9  dot_theta_b
```

Watch 变量：

```text
Chassis.lqr.x[0..9]
Chassis.imu.yaw
Chassis.imu.yaw_total
Chassis.body.side_speed[0..1]
Chassis.body.d_s_raw
Chassis.body.d_s
Chassis.body.dd_s
Chassis.body.dd_s_fused
Chassis.body.s
```

检查要求：

- 推动车体前进时，`dot_s` 方向正确。
- 单侧速度满足 `R*(wheel_speed+d_theta) + L0*d_theta*cos(theta) + d_L0*sin(theta)`，其中 `R*d_theta` 是轮轴定子随腿摆动的速度项。
- 静止时估计速度不会持续明显漂移。当前加速度测量噪声配置为 `1e12`，Kalman 几乎不使用 IMU 加速度，不能将 `d_s` 描述为已经完成速度/加速度融合。
- 左右轮同向转动时主要改变前进速度。
- 左右轮反向转动时不应被误算为明显前进速度。
- 左右腿状态进入 `theta_l/theta_r` 的符号符合离线模型。
- yaw 跨越正负 pi 时，`lqr.x[2]` 跟随连续 yaw，不产生 `2*pi` 跳变。

## 8. K 矩阵与 LQR 输出

Watch 变量：

```text
Chassis.leg[0..1].L0
Chassis.leg[0..1].K_L0_fit
Chassis.lqr.limit_flag
lqrK[4][10]（chassis_control.c 文件静态量）
Chassis.output.T_wheel[0..1]
Chassis.leg[0..1].Tp
```

输出顺序：

```text
0  左轮力矩
1  右轮力矩
2  左腿摆力矩
3  右腿摆力矩
```

检查要求：

- 无论目标腿长是否固定，K 输入都跟随左右腿实际 `L0`，不存在固定 K 分支。
- `0.12m~0.31m` 内 `K_L0_fit` 应等于实际 `L0`，`limit_flag` 应为 0。
- 超出采样范围时 `K_L0_fit` 应停在最近边界，`limit_flag` 应为 1。
- 左右对称状态下，左右 K 和输出应满足模型对称关系。
- 状态微小变化不应导致 K 或输出发生不连续跳变。

## 9. PID 与支撑力

当前配置中的主要参数：

```text
腿长 PID kd = 8000
横滚 PID kp = 3000
PID 输出限幅 = 300N
base_support_force_n = -30N
```

Watch 变量：

```text
Chassis.leg[0].F0
Chassis.leg[1].F0
```

检查要求：

- 静止时支撑力稳定，不应高频大幅振荡。
- 左右水平时，两侧支撑力差值合理。
- 车体横滚时，左右支撑力差应向恢复水平的方向变化。
- 支撑力不应长期卡在 PID 输出限幅。
- `base_support_force_n` 的负号必须与当前 VMC 定义一致，确保腿产生正确的地面支撑方向。

腿长速度或 IMU 噪声较大时，当前较大的微分和比例参数可能迅速使支撑力饱和。启用电机前先在安全零输出状态观察这些中间量。

## 10. 最终输出检查

Watch 变量：

```text
Chassis.output.safe_flag
Chassis.fault
Chassis.output.T_joint_req[0..3]
Chassis.output.I_wheel_req[0..1]
Chassis.output.T_joint[0..3]
Chassis.output.I_wheel[0..1]
```

注意：输出许可关闭或设备故障时，请求数组、`Chassis.output.T_wheel` 和 `Chassis.leg[].F0/Tp` 继续更新，最终命令数组保持为 0。

打开输出后检查：

- 所有命令均受限幅约束。
- 输出许可关闭或设备离线时继续计算中间量，但最终命令必须立即恢复并持续保持零输出。
- 控制计算失败时 `Chassis.fault` 必须包含对应控制或运动学故障，最终命令保持零输出。
- 没有旧命令残留。
- 单个电机命令只作用于对应电机。
- 电机温度、电流和机械冲击处于安全范围。

## 11. 推荐调试顺序

1. 保持三层输出开关关闭，在无动力状态手动转动各电机并移动整车，确认电机映射、反馈方向、IMU 坐标和连续角方向。
2. 确认反馈方向后建立机械基准，标定 DM 电气零点和软件 `angle_offset_rad`；重新上电复查零点可重复性。
3. 在板凳或悬挂状态逐个开放极小的 DM 力矩和 DJI 轮电流，分别确认每个执行器的输出极性；输出方向不得借零点偏置补偿。
4. 重新关闭动力，核对五连杆尺寸、轮半径、控制周期和 K 采样范围；静态及缓慢动态观察 `phi1/phi4/phi0/L0`、速度和十维状态。
5. 进入 `CHASSIS_MODE_BENCH`，先只开关节位置-速度串级环，再以小限幅启用两路当前十维 LQR 轮输出；逐项确认请求量、最终量和故障清零行为。
6. 进入 `CHASSIS_MODE_FOLLOW`，保持固定目标腿长，先调支撑力与 VMC 方向，再进行低增益 Standing；K 仍始终使用实时 `L0`。
7. 固定腿长站立稳定后，依次加入低速前后平移和制动，确认 `s/d_s` 方向、轮速估计及轮电流方向。
8. 平移稳定后再加入 yaw 目标和原地转向，确认连续 yaw、左右轮差动符号及航向目标进入模式时无阶跃。
9. 最后逐步加入变腿长、扩大目标和限幅，再分别验证小陀螺、爬台阶、自救等高级模式。`0.31m` 以上的 K 需先重新建模，不能仅解除固件限幅。

## 12. 每次上电前检查

- 机器人已架空、使用板凳或安装保护绳。
- 急停和主电源能够立即断开。
- 六个电机 CAN ID 与程序映射一致。
- DM 已进入正确控制模式。
- IMU 已完成初始化、温控和零偏稳定。
- 腿部没有处于机械死点或极限位置。
- 软件处于零力矩模式。
- 所有输出限幅仍为当前调试阶段允许的小值。
- Watch 中两侧 `valid_flag == 1`；开放输出前还必须确认 `Chassis.fault == CHASSIS_FAULT_NONE` 和全部设备在线。
- 现场人员远离轮子、连杆和夹伤区域。
