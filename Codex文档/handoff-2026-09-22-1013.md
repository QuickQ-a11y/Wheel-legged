### ⚠ 一条值得记住的排查教训

本轮实际是**三个故障叠加**（接收机输出模式停在 PPM/S.BUS + 座子带硬件反相器
RXINV 没开 + 拨杆方向判反）。中途我用正确的假设（需要开 RXINV）做了一次验证，
但当时 PPM 那个故障还在，**拿到了假阴性，于是把正确的假设丢掉了，绕了一大圈**。

**结论：多故障叠加时，单独验证一个假设得到的否定结论无效。**
另外 `uartErrorCount` 在极性对错两种情况下都会涨，**它不能当判据**；
有区分度的是 `rxEventCount`（判据表在 `Gimbal/CLAUDE.md`）。

## 2. 当前卡点：i6X 只有一个三档开关

这是**下一步"模式分配"的真正阻塞项**，且现在已经有实测数据可以做决定了。

- 实测：SwA~SwD 落在下标 6/7/8/9；**只有 SwC（下标 8）是三档**，其余是两档。
- 底盘现有语义需要**两个**三档：右拨杆管急停/待命/运行，左拨杆管 STEP/FOLLOW/TOP。
- 三条出路（菜单挪位置 / 换三档开关模块 / 混控拼三档）的对比表、手册章节号、
  具体操作步骤，都在 **`Gimbal/CLAUDE.md` §⚠ i6X 默认只有一个三档开关**。

### 已定的约束：UP = 卸力

用户实测：**发射机要求所有杆位于 UP 才允许开机**（否则报警）。
所以 UP 是唯一保证的上电初始状态，**必须映射为最安全的模式（卸力）**。

这条同时决定了两件事：
1. `IA10B_ConvertSwitch` 的方向不能反（i6X 是上小下大 UP=1000/DOWN=2000）。
   `test_ia10b.c` 的 `testSwitchThresholds` 已钉死，变异测试验证过能捕获翻转。
   **方向反了会让"急停位置"变成"运行位置"。**
2. 通道值残留 0 时落在 UP 一侧，退化方向是安全的。

### 3.2 板间通信

**大概率不用改**：云台往下发的是归一化后的 `Remote_t` 快照，不是裸通道，
换接收机不影响协议。真要动之前先跑这条 diff（命令在根 `CLAUDE.md` §板间协议契约）：

```bash
diff <(grep APP_BOARD_ Chassis/User_File/1_Middleware/0_Common/app_config.h) \
     <(grep APP_BOARD_ Gimbal/Real/User_File/1_Middleware/0_Common/app_config.h)
```

⚠ 改协议后**必须**跑 `Gimbal/Real/Tests/test_board_protocol.c`（它同时链两个工程的
`device_board.c`，是板间协议的唯一回归保障；编译命令在该文件顶部注释里）。

### 3.3 底盘接入

`Chassis/` 目前**没有** IA10B 后端，只有 DR16。移植时把云台这三样搬过去：
`2_Device/Communication/IA10B/`、`task_remote.c` 顶部的编译期别名块、
`app_config.h` 的 `APP_REMOTE_BACKEND` / `APP_IA10B_DB`，
并在 `Chassis/CMakeLists.txt` 的 `target_sources` 和 `target_include_directories`
**两处**都注册（CubeMX 不管 `User_File/`）。

⚠ 但底盘接收机在**云台板**上（DR16/iA10B 都挂云台 UART5），底盘只从 FDCAN3 收
`Remote_t`。**所以底盘大概率根本不需要 IA10B 后端**——先确认需求再动手，
别照搬。
