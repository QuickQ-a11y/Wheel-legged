# HERO_LEG对比与模式扩展说明

## 1. 对比边界

参考工程：`/home/quickq/code/STM32/Others/HERO_LEG/Chassis`。

当前工程和HERO_LEG都使用十维状态、腿长相关LQR、VMC、轮腿速度估计和实机状态机，但两车的机械参数、执行器方向、质量、控制周期和K系数不相同。本文只引入控制组织和可解释观测方法，不复制原车阈值、PID或增益倍率。

## 2. 逐项结论

| 项目 | HERO_LEG做法 | 当前工程结论 |
|---|---|---|
| 轮速估计 | 轮线速度、`R*d_theta`定子转动、腿摆和平动速度相加 | 已补齐原实现缺少的`R*d_theta`项，并使用整车前向加速度作为Kalman输入 |
| 打滑检测 | 比较轮速yaw与IMU yaw、轮速与车速、轮速增量与IMU加速度 | 已引入三类残差，并增加低通、进入/退出持续时间和滞回；本轮仅供Watch |
| 离地检测 | 由虚拟支撑力、腿部加速度和IMU Z加速度估算法向力 | 已增加关节反馈力矩到虚拟力的逆映射和名义法向力估计；本轮仅供Watch |
| 小陀螺 | 屏蔽X位移和yaw位置反馈，并对部分姿态反馈乘经验倍率 | 已屏蔽`s/fai`，保留速度和姿态反馈；未复制1.2/3.0/1.4经验倍率 |
| 爬台阶 | 抬腿接近，轮请求和腿角判断碰撞，收腿摆动，碰撞后轮输出清零 | 已实现四阶段状态机，并增加反馈力矩确认、持续时间和各阶段超时 |
| 模式增益 | 同一腿长拟合K上按模式修改反馈项 | 当前使用统一K点乘和状态缩放；没有引入未经本车模型验证的独立K或倍率 |
| 高速转向支持力 | 参考代码含姿态/载荷经验补偿，但参数依赖原车 | 已按名义质量和质心高度计算差动支持力建议值，仅供Watch |
| 气弹簧 | 按原车气弹簧几何计算支撑力前馈 | 当前实车没有气弹簧，不引入该补偿 |

## 3. 已实现控制链

### 3.1 小陀螺

通用输入接口新增`REMOTE_MODE_TOP`和横向轴：

```text
左摇杆前后/左右
    -> TOP入口航向坐标中的二维速度向量
        -> 按 yaw_total - top_yaw_anchor 投影到当前车体前进方向
            -> 十维LQR的 dot_s 目标

右摇杆左右
    -> +/-2 rad/s yaw速度目标
        -> 十维LQR的 dot_fai 目标
```

TOP最大平移速度为`0.25 m/s`。`s`和`fai`反馈缩放为0，其余八个状态保持1；状态顺序、K拟合和VMC映射均未改变。

### 3.2 辅助爬台阶

```text
PREPARE  把双腿升到接近腿长，车速目标为0
APPROACH 限制为正向0~0.10 m/s，检测左右接触并分别锁存
CLIMB    收腿并用腿角PID摆到峰值，实际轮输出清零
RECOVER  恢复腿角和遥控腿长，稳定后回到STANDING
```

接触条件要求同一侧同时满足：轮LQR请求力矩、轮反馈电流换算力矩和腿角阈值，并持续`contact_time`。左右均锁存后进入CLIMB。CLIMB和RECOVER只清零`output.I_wheel`，继续保留`output.T_wheel`和`output.I_wheel_req`供Watch。

每个阶段都有独立超时。超时进入`CHASSIS_ZERO_FORCE`并保留`CHASSIS_FAULT_STEP_TIMEOUT`，重新请求前必须先切换到其他模式。

## 4. 只读观测器

`chassis.observer`当前提供：

- 左右轮纵向速度残差、轮速yaw残差和速度增量/IMU加速度残差。
- 左右打滑候选、确认标志和进入/退出计时。
- DM反馈力矩反解的虚拟支撑力、摆力矩和有效标志。
- 法向支持力、名义静载比例、离地/落地候选和滞回结果。
- IMU与运动学横向加速度、残差和两种差动支持力建议值。

质量仍采用MATLAB名义值：机体`10 kg`、单腿`0.5 kg`、单轮`1 kg`，机体质心到髋轴`0.04 m`。因此离地阈值和转向支持力不能作为当前实车控制依据。

## 5. 未直接复制的参考逻辑

HERO_LEG中发现以下风险，当前实现未照搬：

1. 1 kHz任务中的位移积分使用固定`0.01 s`，与实际周期不一致。
2. 两处模式条件重复检查左侧打滑标志，漏掉右侧标志。
3. 台阶动作没有阶段持续时间和超时，传感条件不满足时可能永久停留。
4. 部分VMC开方和除法缺少输入有效性处理。
5. 小陀螺姿态增益倍率、离地阈值和碰撞阈值都绑定原车参数。

## 6. 当前安全状态

以下三层开关仍全部为0：

- `APP_CHASSIS_OUTPUT_ENABLE`
- `Chassis_Config.output.joint_flag`
- `Chassis_Config.output.wheel_flag`

因此新增模式会完整计算中间量和请求量，但不会产生非零物理命令。DR16当前拨杆映射保持不变，TOP和STEP只通过通用输入接口提供请求，尚未绑定DT7键位。
