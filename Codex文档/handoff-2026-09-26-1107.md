## 1. VMAX：TMAX 那个坑的另一半，症状相反

底盘关节是 **4 台 J8009P，寄存器 VMAX = 45**（用户确认）。固件的
`APP_DM_VEL_MIN/MAX` 从 2.4 版起一直是 **±30**——那是 J4310 的值。

git 考古：

| 提交 | 量程 |
|---|---|
| `3295c71`（2.2） | `VEL ±45`，是对的 |
| `e202dc9`（2.4） | 整体换成 **J4310** 的 `VEL ±30 / TOR ±10`，注释原文"范围按当前 J4310 协议配置" |
| `e3339d4`（4.14） | TMAX 事件：`TOR` 修成 ±40。**`VEL` 没人动** |

`app_config.h` 那句"范围按当前 J8009P 协议配置"早就改了，**对速度这一行一直是假的**。

**为什么症状和力矩相反**：命令帧只用力矩通道（`device_motor_dm.c` 里位置/速度/KP/KD
字节全置 0），速度量程**只在解码处用**。没有编码侧，误差就**不会往返相消**——
表现为 2.4 版至今**所有关节速度读低 33%**（真实 × 30/45），而不是力矩那样"看起来都对"。

## 2. 修正怎么做的：三类消费者，处理方式不同

关节速度只有两个入口：`chassis_control.c` 的 VMC（→ `d_L0`、`d_phi0`）和
`Joint_Control` 的速度环。往下分三类：

| 类别 | 例子 | 处理 |
|---|---|---|
| 纯关节速度量，**精确**差 1.5 倍 | `d_L0`、`d_H`、`d_phi0`、关节速度 | 对着旧读数**实机验证过**的手调参数按比例折算，行为不变 |
| 混合量，无单一系数 | `d_theta = d_phi0 + 陀螺`、`d_s`（轮速+腿速）、`Fn` 惯性项 | **不能折算**，只能上机重测 |
| 物理单位设计的 | LQR K、MPC、LESO、速度卡尔曼、**从 ZJU 抄的阈值** | **不动**——之前吃的是错输入，现在第一次按原意生效 |

**已折算**（`4.26`，都从 HEAD 里实机验证过的值出发）：

| 字段 | 原 | 新 |
|---|---|---|
| `leg_length_pid.kd` | 300 | 200 |
| `recovery.joint_angle_pid.kp` | 10 | 15 |
| `recovery.joint_angle_pid.outputLimit` | 100 | 150 |
| `recovery.joint_speed_pid.kp` | 4 | 2.667 |

关节串级的推导：两环 ki=kd=0，要求对任意角度误差和真实速度给出同一个力矩，
⇒ `kp_s × 30/45`、`kp_a × 45/30`、外环限幅 × 45/30。速度环的 `outputLimit = 20` 是力矩，不折算。

⚠ **外环限幅必须跟着折算**，只折 kp 不折限幅在外环饱和时不中性——
`test_chassis_vmc` 的 `test_vmax_rescale_is_behavior_neutral` 专门有一组"外环饱和、
内环不饱和"的点来抓这个。写这条用例时第一版没抓住：内环力矩也饱和在 ±20，把差别盖住了。

⚠ **`observer.land_d_L0_*` 三个故意没折算**：注释写着"阈值取 ZJU 式93原值"，是物理单位
参考值、不是本车手调的。修正前实际触发点比 ZJU 宽 1.5 倍，**修正后落地判据会更灵敏**。
计划里一开始把它们归错了类，读到这句注释才改过来。

⚠ **模型推导的环在动态工况下会比以前更有阻尼**（压腿、台阶、落地）。那是正确行为，
但它是一个行为变化。站立时 `d_L0 ≈ 0`，差别很小。

## 3. 对气弹簧的影响

- **弹簧力本身不受影响**：`VMC_Spring_Force_Calc` 只依赖 `L0`、几何常量和 `spring->force`。
- **但它卡着开启弹簧的最后一个前提**：观测器力类阈值重标。`Fn` 的惯性项吃的正是
  `d_L0`、`dd_L0`、`d_theta`——**必须在 VMAX 修正之后标**，顺序反了标出来的还是错的。
- ⚠ 站立时惯性项趋零，**静态下 `Fn_ratio` 完全正常，静态标定查不出这个错**，只在动起来时偏。

## 4. `F0_gravity_scale = 1.21` 不用改

用户怀疑它是 TMAX 错的时候给的。**不是**：它在 `e3339d4`（4.14）引入，正是修 TMAX、
按称重定 `body_mass = 16.43` 的同一个提交。推导在 `chassis_config.c` 那段注释里：
站立实测稳态命令 F0 平均 97.5 N / 静力学需求 80.6 N = 1.21，多出的 16.9 N 是
髋部分担的腿自重 + 连杆和同步带静摩擦。

反证：如果当时固件还是 ±25（命令放大 1.6 倍），97.5 N 命令实际是 156 N，
多出 75 N——没有哪种摩擦解释得了。16.9 N 的物理解释只在正确标度下成立。
VMAX 也不影响它：那是静止稳态测量，速度项不参与。

⚠ 唯一的附注：它是**气弹簧拆着**时标定的。作为总轴向需求原则上仍成立，但开弹簧补偿后
站立时核一下关节力矩是否掉到预测的 0.3~1.9 N·m；对不上调这个系数，**别动 `body_mass`**。

## 5. ⚠⚠ 上机安全：当前工作区的组合站着就可能倒

当前状态：**气弹簧已物理装上** + `spring.enable_flag = 0` + `off_ground_act_flag = 1`（活动块）。

`enable_flag = 0` 时观测器看不到弹簧那份力，`Fn` 只剩电机分担的部分。站立时弹簧给
87~111 N、需求 97.5 N，电机那份只剩 −14~+10 N，**`Fn_ratio` 从 ~1.0 掉到 0.1~0.3，
正好跨在 `off_force_ratio = 0.20` 上**，腿越长越容易掉到阈值下面。

而 `chassis_config.h` 对 `off_ground_act_flag` 的注释原话：掩码那一项在 `all_off_flag`
误触发时会让**站着的车瞬间失去位移、速度、航向和俯仰全部反馈直接倒地**。

用户选择自己处理，本次**没有改** `off_ground_act_flag`。建议的上机顺序：

1. `off_ground_act_flag = 0`
2. `body_mass` 改回 16.43（称重值，见第 6 节）
3. `spring.enable_flag = 1`
4. 站立看 Watch：关节力矩应掉到 0.3~1.9 N·m、`Fn_ratio ≈ 1.0`、站高正确
5. 跑一轮正常行驶和小陀螺，重标 `off_force_ratio` / `land_force_ratio` 等，
   确认 `all_off_flag` 一次都不误触发
6. 然后才 `off_ground_act_flag = 1`

## 7. 滚轮三档腿长（`4.25`）

4.20 遥控大改时滚轮被征用成 FS-i6X 的 VrA（选模式组），原来的滚轮选腿长随
`remote_input.c` 整个文件删掉了。DT7 只有一个滚轮，两个职责按数据源分：

- 底盘**本地插的 DT7/DR16**：滚轮 = 三档腿长，模式组锁死低组
- 云台经板间 CAN 转发的 **FS-i6X**：VrA 仍然选模式组

判据是设备层 `Board_IsOnline()`（`task_remote.c` 选源用的也是它）。底盘那份
`app_config.h` 里**没有** `APP_REMOTE_BACKEND`，所以不能也不需要编译期开关。

三档常量与 4.20 之前逐字节一致。⚠ **名字不是按长度排的**：M(0.18) 才是最短档，
S(0.28) 反而更长；**L=0.38 超过活动配置的 `lqr.L0_max = 0.35`**，拨长档会夹紧 K 拟合。
