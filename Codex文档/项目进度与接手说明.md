## 5. 启动和任务流程

CubeMX生成的`MX_FREERTOS_Init()`创建默认任务，并初始化：

```text
CAN_Task_Init()
Remote_Task_Init()
Chassis_Task_Init()
IMU_Task_Init()
USB_Task_Init()
```

默认任务中只调用一次`MX_USB_DEVICE_Init()`，不要在`USB_Task_Init()`中重复初始化USB Device。

任务优先级和栈：

| 任务 | 优先级 | 栈大小 |
|---|---|---:|
| `ImuTask` | Realtime | 3072 B |
| `ChassisTask` | High | 4096 B |
| `RemoteTask` | AboveNormal | 2048 B |
| `UsbTask` | AboveNormal | 3072 B |
| `CanTask` | Normal | 2048 B |
| `defaultTask` | Normal | 1024 B |

FreeRTOS tick为1 kHz。IMU和底盘控制统一使用：

```c
APP_CTRL_TICKS = 1U
APP_CTRL_DT_S = 0.001f
```

IMU和底盘分别测量自己的实际`dt`。正常为`0.001 s`，任务延迟时允许出现`0.002 s`等值。底盘PID、速度Kalman和位移积分使用`Chassis.dt`，不再复用IMU单次采样周期。

## 7. CAN和电机

### 7.1 外设

- FDCAN1和FDCAN2均配置为Classic CAN，1 Mbit/s。
- FDCAN1：PD0 RX、PD1 TX。
- FDCAN2：PB5 RX、PB6 TX。
- 自动重发关闭：`AutoRetransmission = DISABLE`。
- 发送失败不等待、不重发旧帧，下一周期继续发送最新命令。
- BusOff时执行轻量stop/start恢复。
- 只接CAN分析仪时，分析仪必须工作在会发送ACK的正常模式，静默监听模式不会ACK。

### 7.2 电机和CAN映射

| 电机 | 数组下标 | 总线 | 命令ID | 反馈CAN ID | 控制关节 | `scale` | `ratio` |
|---|---:|---|---:|---:|---|---:|---:|
| 左前髋 | 0 | FDCAN1 | `0x001` | `0x011` | 左腿`phi4` | `+1` | `0.75` |
| 左后髋 | 1 | FDCAN1 | `0x002` | `0x012` | 左腿`phi1` | `+1` | `0.75` |
| 右前髋 | 2 | FDCAN1 | `0x003` | `0x013` | 右腿`phi4` | `-1` | `0.75` |
| 右后髋 | 3 | FDCAN1 | `0x004` | `0x014` | 右腿`phi1` | `-1` | `0.75` |
| 左轮 | 0 | FDCAN2 | `0x200`字节0~1 | `0x201` | - | - |
| 右轮 | 1 | FDCAN2 | `0x200`字节2~3 | `0x202` | - | - |

四台DM分别配置独立反馈ID `0x11~0x14`。设备层按总线和反馈ID分流，并校验`D[0]`低4位等于对应控制ID `1~4`。DM设备层保留原始MIT坐标，不处理机械安装方向；关节方向由`scale`处理，主动杆角/电机角传动比由`ratio`处理。

### 7.3 达妙MIT控制

当前DM命令结构体只包含`torqueNm`。发送时仍使用8字节MIT帧，但只使用力矩通道：

- 前6字节置0。
- 最后12 bit填入力矩编码。
- 不下发位置、速度、KP和KD控制量。
- DM调试助手的`PMAX`保持电机默认值`12.5 rad`；控制帧与反馈帧的16位位置字段均按`-12.5~+12.5 rad`映射。当前发送纯力矩帧，位置字段不参与实际输出。
- 反馈位置经过定点解码后单位为弧度，并且可以连续越过`±pi`；速度和力矩反馈/力矩给定暂按`-30~+30 rad/s`、`-10~+10 N*m`处理。
- 这些数值是定点编解码刻度，不是机械安全限幅。
- 底盘连续关节力矩限幅当前配置为`3.5 N*m`。

DM使能/失能使用`FF FF FF FF FF FF FF FC/FD`特殊帧。模式变化时只缓存发送一次，失败不会重发。实机调试必须观察电机状态是否确实进入MIT模式。

DM位置反馈解码后保留`positionWrappedRad`单圈角，并按`2*pi`展开到`positionRad`连续角。首次反馈或掉线超过50 ms后重新建立基准，不恢复断电或长时间掉线期间的历史圈数。

### 7.4 DJI轮电机

当前轮电机按直驱、传动比1配置：

- 转矩常数：`0.02 N*m/A`。
- 连续轮端力矩限幅：`0.16 N*m`。
- `torque_to_current = 40960 count/(N*m)`。
- 连续电流对应命令限幅：`8192`。
- 电调完整命令范围仍为`-16384~+16384`，对应约`-20~+20 A`。

这些换算尚未通过本车左右轮实际方向和力矩测试确认。

## 8. USB CDC通信

### 8.1 外设和缓存

- 使用`USB_OTG_HS`内部Full Speed PHY。
- PA11为USB_DM，PA12为USB_DP。
- USB时钟源为HSI48，48 MHz。
- CDC设备，不启用USB DMA。
- 接收环形缓冲：2048 B。
- 状态发送FIFO：32帧。
- 单次CDC IN最多批量发送16帧。
- 当前状态帧名义发送周期：1 ms，约1000 Hz。

接收中断只把字节写入环形缓冲，CRC、流式解析和业务回调在USB任务中执行。解析器支持半帧、连包、前置噪声和CRC错误后重新同步。

### 8.2 数据帧

帧头为7字节：

```text
sof(1) + data_length(2) + seq(1) + crc8(1) + cmd_id(2)
```

CRC8校验前4字节，CRC16校验除末尾CRC16外的完整数据包。16位字段低字节在前。

状态Payload：

```text
roll, yaw, pitch, bulletSpeed, heat, enemyColor, mode
```

控制Payload：

```text
yaw, pitch, shoot
```

当前发送命令号：

```c
usbTaskTxCommandId = 0x0002U
```

`roll/yaw/pitch`来自IMU。`bulletSpeed/heat/enemyColor/mode`暂无真实数据源，当前为0，可在Live Watch中临时修改`usbTaskTxData`。

### 8.3 必须先解决的SOF冲突

当前源码存在明确不一致：

```c
#define USB_PROTOCOL_SOF 0xA0U
```

但同一头文件注释、`代码风格要求.md`和最初协议约定都写SOF应为`0xA5`。

现有USB测试使用`USB_PROTOCOL_SOF`宏构造测试帧，因此即使宏值错误，测试仍会通过，不能发现该协议兼容问题。接手后必须先与当前上位机确认实际发送和期望值，再统一宏、注释、测试固定向量和文档。

此前用户通过Watch观察到：


### 8.6 DT7/DR16遥控器

- 使用板载反相后的`UART5_RX/PD2`，配置为`100000 baud`、8位数据、偶校验、1停止位和无流控；HAL中对应`UART_WORDLENGTH_9B + UART_PARITY_EVEN`。
- `DMA1_Stream3`使用Normal模式，配合UART IDLE事件接收固定18字节DBUS帧；DMA缓冲位于`RAM_D1`专用段，不放入DMA无法访问的DTCM。
- 四个11位通道必须位于`364..1684`，S1/S2必须为`1/2/3`，否则整帧不更新控制状态。
- 键盘位序按本家代码解析为`W S D A Shift Ctrl Q E R F G Z X C V B`。
- 最后两个字节优先按本家代码解析为拨轮；若不在`364..1684`内，仅令`dial=0`和`dialValid=0`，不会让整帧离线，以兼容旧手册的保留字段定义。
- 连续2帧有效数据后判定上线；超过100 ms没有有效帧后离线。离线时全局`Remote`回中，原始解析值和原始帧仍保留在调试快照中。
- `device_dr16.*`只负责DBUS原始解析和DR16控件适配；独立`RemoteTask`负责DMA邮箱、在线检测和诊断发布。
- `RemoteTask`向底盘发布`Remote_t Remote`全局一致快照；其中左右摇杆和滚轮均归一化到`-1~1`，左右拨杆使用通用枚举。底盘不依赖DR16帧长、原始通道范围或S1/S2编码。

| 输入 | 底盘目标 |
|---|---|
| 左摇杆上下 | 前进速度`-0.5~+0.5 m/s` |
| 右摇杆左右 | 以摇杆开始偏转时的连续yaw为锚点，给定`-1.0~+1.0 rad`相对航向；符号按SPR取反 |
| 拨轮`> +400` | 目标腿长`0.15 m` |
| 拨轮`-400..+400` | 目标腿长`0.20 m` |
| 拨轮`< -400` | 目标腿长`0.25 m` |

- 两个已使用摇杆轴采用`+/-10`死区，死区外重新映射到`-1..+1`，满杆仍可达到完整目标。
- 速度目标变化率限制为`1.0 m/s^2`，连续航向目标变化率限制为`2.0 rad/s`，腿长复用恢复配置中的`L0_rate`。
- 正常FOLLOW模式下左摇杆左右、右摇杆上下和键鼠不参与底盘控制；BENCH模式下左右摇杆分别调节两条腿的`L0/phi0`目标速率。
- S1对应协议中的右侧开关字段，向下为急停：只关闭最终输出许可并将速度目标清零，不切换到`CHASSIS_MODE_ZERO_FORCE`，因此VMC/LQR/PID中间量仍继续计算。
- S2对应协议中的左侧开关字段：上位请求`FOLLOW`，中位请求`BENCH`，从非下位切到下位时单次触发`SELF_SAVE`。

- 上电、遥控器重新上线或解除S1急停后，必须先看到S2回到上位才重新建立控制许可；这可避免恢复通信时直接进入板凳或自救。
- 自救真正完成并回到`CHASSIS_STANDING`后自动切回`FOLLOW`；S2回到上位前保留自救触发锁，防止下位重复触发。
- 遥控器离线或S1向下会置位`CHASSIS_FAULT_REMOTE`，最终四路关节力矩和两路轮电流清零，但控制请求量继续保留供Watch观察。

## 9. 底盘控制

### 9.1 模式与状态

外部模式表示操作者意图：

| 模式 | 行为 |
|---|---|
| `CHASSIS_MODE_ZERO_FORCE` | 主动零力矩 |
| `CHASSIS_MODE_FOLLOW` | 正常站立、速度和连续航向控制 |
| `CHASSIS_MODE_TOP` | 小陀螺二维平移投影和偏航速度控制 |
| `CHASSIS_MODE_SELF_SAVE` | 倒地转腿和重新站立 |
| `CHASSIS_MODE_BENCH` | 独立小板凳姿态控制 |
| `CHASSIS_MODE_STEP` | 辅助爬台阶 |

内部状态决定本周期调用的控制入口：

| 状态 | 入口 |
|---|---|
| `CHASSIS_STANDING` | `Chassis_Control()` |
| `CHASSIS_ZERO_FORCE` | `Chassis_Zero_Output()` |
| `CHASSIS_FALLEN` / `CHASSIS_FALLING_TO_STAND` | `Chassis_Recovery()` |
| `CHASSIS_BENCH` | `Chassis_Bench()` |
| `CHASSIS_STEP` | `Chassis_Step()` |

STEP内部阶段为`PREPARE -> APPROACH -> CLIMB -> RECOVER`。`Chassis_State_Update()`只选择状态，不计算VMC/PID/LQR；设备故障保留中间量并封锁最终输出，姿态越界、逆解无效、VMC奇异或阶段超时会进入零力状态。

### 9.2 主流程

`chassis_task.c`每轮按以下顺序执行：

```text
反馈更新
    -> 状态更新
        -> switch-case选择控制状态
            -> 正常站立调用Chassis_Control()
            -> 恢复、板凳和台阶调用各自控制入口
                -> 写入DM和DJI发送缓存
```

`Chassis_Control()`内部保持SPR风格的顺序：

```text
左右腿VMC状态由任务入口先更新
    -> 轮腿速度观测和IMU前向加速度输入
        -> 二维Kalman更新（当前加速度测量噪声为1e12，实际主要使用轮腿速度）
            -> 十维状态集中赋值
                -> 腿长PID、基础支撑和roll补偿
                    -> 按左右腿长生成K矩阵
                        -> 四路LQR广义输出
                            -> VMC映射到四个关节力矩
                                -> 关节力矩和轮电流限幅
```

### 9.4 当前配置

**实机整定期数值随时在变，以 `chassis_config.c` 为准**，本节只说明结构。

- 遥控三档腿长在 `app_config.h` 的 `APP_RC_LEG_S/M/L`；`Chassis_Config.leg[].target_L0`
  只是无遥控目标时的兜底值。两者是**独立**的两套来源，改一个不影响另一个。
- K腿长来源：左右五连杆实时 `L0`；`lqr.L0_min/L0_max` 必须落在 MATLAB 采样范围内，
  超出会被限幅并置 `Chassis.lqr.limit_flag`，**禁止外推**。
- 支撑力不再是常数：`F0 = 腿长PID + roll补偿 + 重力前馈`，其中重力前馈为
  `0.5 * Chassis_Model_Mass() * gravity * F0_gravity_scale * cos(theta)`，随腿摆角投影。
  整定时先调 `F0_gravity_scale`，不要回头改 `model` 里的质量。
- LQR 误差在进 K 点乘前按 `lqr.error_limit[]` 逐状态限幅（`0` 表示不限）。
  `Chassis.lqr.error[]` 是限幅后真正进 K 的误差，某一路输出异常时先看它。
- 板凳腿长/腿角用摇杆给**速率**再积分，天然是斜坡；站立腿长目标直接赋值，无斜坡。
- 速度Kalman已启用，但加速度测量权重仍近似关闭，不能视为已完成IMU加速度融合。
- 每条输出通道只有一个限幅点：关节 `output.joint_T_limit`，轮 `wheel.T_limit`。
  不要再加第二处。

### 9.6 电机零位和极性

本车两侧采用相同规范几何：后髋电机控制后传动杆`phi1`，前髋电机控制前传动杆`phi4`，`phi0/phi1/phi4`均绕车体`+Y`增大。从车辆左侧观察时`+Y`指向观察者，逆时针旋转使角度增大；从右侧观察时视觉方向相反。左右镜像姿态的对应角数值相等，不使用裸值大小关系判断构型。同步带不交叉，电机轴与主动杆轴同向，电机带轮与主动杆带轮齿数比为`3:4`。

当前关节配置为：

```text
左phi1：motor=1, angle_offset=pi/2, scale=+1, ratio=0.75
左phi4：motor=0, angle_offset=pi/2, scale=+1, ratio=0.75
右phi1：motor=3, angle_offset=pi/2, scale=-1, ratio=0.75
右phi4：motor=2, angle_offset=pi/2, scale=-1, ratio=0.75
```

四台电机均在主动杆竖直向下时设置电气零点，因此`p_motor=0`对应`phi1/phi4=pi/2`；虚拟腿竖直向下对应`phi0=pi/2`，LQR换算使用`theta=phi0-pi/2+pitch`。令`joint_scale=scale*ratio`，则`phi=offset+joint_scale*p_motor`、`d_phi=joint_scale*v_motor`、`T_motor=joint_scale*T_geometric`、`T_geometric=T_motor/joint_scale`。

- 零位错误改`angle_offset_rad`。
- 单个关节整体方向错误只改对应`scale`。
- 禁止在DM设备层、VMC公式、PID或LQR增益中增加第二套方向修正。
- `wheel.left_scale/right_scale`同时作用于轮速反馈和轮电流命令；单侧方向错误只修改对应一项，禁止在K矩阵中补反号。

## 10. 当前安全状态

当前静态输出配置为：

```c
APP_CHASSIS_OUTPUT_ENABLE = 1U
Chassis_Config.output.joint_flag = 1U
Chassis_Config.output.wheel_flag = 0U
```

这表示髋关节分支具备进入最终输出门的条件，轮电流静态分支仍关闭。实际输出还必须同时满足`Chassis.enable_flag`、IMU/DM/DJI/CAN/遥控器故障、几何和姿态保护、`output.safe_flag`、分路开关及限幅条件。

此外：

- `Chassis.enable_flag`初始化为0。
- `Chassis.mode`初始化为`CHASSIS_MODE_ZERO_FORCE`。
- 底盘任务上电后自动发送DM协议使能帧以取得反馈，但`dmSafe`和最终命令仍保持零力矩。
- 遥控任务通过`Chassis_Remote_Update()`维护`Chassis.enable_flag`、运动目标和外层模式；三层静态输出开关仍保持关闭，不会因此产生非零实机输出。
- 选择非零控制模式后，未开放输出或IMU、DM、DJI、CAN、遥控器故障不会阻断VMC/LQR中间量计算，只会封锁最终电机命令。
- 遥控器离线或S1向下会置位`CHASSIS_FAULT_REMOTE`；重新上线或解除急停后还需S2回到上位，才重新打开动态输出许可。
- 正常站立模式会调用十维LQR/VMC控制器。
- 倒地和重新站立使用`CHASSIS_FALLEN -> CHASSIS_FALLING_TO_STAND -> CHASSIS_STANDING`两段式状态链。
- 板凳和恢复模式都会计算关节位置串级控制请求；板凳模式另外计算十维LQR的两路轮电流请求，自救两个阶段的轮请求保持为0。
- 故障时`T_joint_req`和`I_wheel_req`保留本周期请求，最终`T_joint`和`I_wheel`必须为0。
- DM可以保持协议使能以取得反馈，但协议使能不等同于开放底盘动力输出。
- IMU、电机和CAN输出故障清除后会先重置PID、Kalman、位移和yaw目标，再自动恢复输出许可判断。
- 逆运动学无解、VMC奇异、姿态保护或阶段超时仍会进入零力状态。

不要一次打开全部开关。正确顺序是保持总开关关闭，先完成机械、状态和方向检查，然后在板凳或悬挂条件下逐个电机使用极小限幅验证。

### 11.3 FreeRTOS和HardFault

```text

```

FreeRTOS已启用`configCHECK_FOR_STACK_OVERFLOW = 2`。如果发生任务栈溢出，钩子会保存任务名并停止运行。

历史上曾出现运行一段时间后进入HardFault，读取到：

该历史问题没有形成确定根因。当前HardFault处理器只进入死循环，没有自动保存寄存器。如果再次发生，需要重新采集异常栈帧、CFSR/HFSR、当前任务名和各任务栈高水位，不能仅根据`Tmr Svc`名称断定软件定时器栈溢出。

2. 用 `Chassis.lqr.error[]` 观察哪一路状态主导输出，据此调 `lqr.error_limit[]`。
