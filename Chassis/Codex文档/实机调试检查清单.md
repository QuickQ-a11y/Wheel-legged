用于上电、标定、低力矩测试和闭环调试。

**本文不复制任何可调参数值。** 上一版正是因为把 PID 增益、K 范围、轮半径抄进文档，代码一改就全错。所有数值一律指向源码位置，看数就去看源码。

**当前活动配置块是 `chassis_config.c` 顶部的 `#define BIG_WHEEL_LEG`。** `#ifdef LITTLE_WHEEL_LEG` 那一大段不参与编译——查任何参数前先确认自己看的是活动块。

## 0. Watch 窗口分组

`Chassis` 有约 340 个可观测标量，全加进 Watch 既看不过来也拖慢刷新。按需分组添加，不要展开整个结构体。

**A 组 常驻**

| 变量 | 看什么 |
|---|---|
| `Chassis.fault` | 第一个要看的，非零就没有输出。位定义见 `chassis_control.h` |
| `Chassis.state` / `Chassis.mode` | 内部状态机 / 外部请求模式 |
| `Chassis.output.safe_flag` | 置位表示最终命令被清零 |
| `Chassis.dt` | 越界会回退，异常说明任务调度有问题 |
| `Chassis.leg[0/1].valid_flag` | 五连杆本轮是否有数学解 |
| `Chassis.dm_motor[0..3].err_state` | `0`失能 `1`使能 `8~E`错误 |

**B 组 站立与平衡** —— `Chassis.lqr.x` / `.target` / `.error`（各占一条），`Chassis.leg[0/1]` 的 `L0`、`theta`、`F0`、`Tp`。

> `lqr.error` 是**限幅后**真正进 K 点乘的量。某一路输出被单个状态主导时，第一个看它。

**C 组 输出链路** —— `Chassis.output` 的 `T_wheel`、`T_joint_req`、`T_joint`、`I_wheel_req`、`I_wheel`，加 `Chassis.imu.pitch`。

> `_req` 是请求量、无后缀是过完安全门的实际命令。两者不等 = 被门拦下了。

**F 组 LESO 扩张状态观测** —— `Chassis.leso` 的 `d_hat[0..3]`（四路总扰动估计，N*m，顺序同输出：左轮、右轮、左腿摆、右腿摆）、`gate_flag`、`init_flag`、`fit_limit_flag`，加 `Chassis.leso.leso.innovation[]`。

> `d_hat` 与四路力矩同单位，直接和 `output.T_wheel`、`leg[].Tp` 比大小就能判断合不合理。
> `innovation` 是 `y - x_hat`，收敛后应接近 0；持续不收敛说明贴的系数或输入口径不对。
> `Chassis_Config.leso.comp_scale` 是补偿接入比例：0 只观测不补偿（`gate_flag` 恒为 0），1 足额减去。
> 上机顺序是先置 0 确认 `innovation` 收敛、`d_hat` 量级合理，再按 0.2 步长往上抬。

**D 组 关节校零** —— `Chassis.leg[0/1]` 的 `phi1`、`phi4`、`phi0_total`，`Chassis.dm_motor[0..3].position_rad`。

> 判据：腿竖直向下时 `phi1 + phi4 = pi`。

**E 组 速度融合** —— `Chassis.body` 的 `d_s_raw`、`d_s`、`dd_s`、`dd_s_fused`。

**平时不要展开**：`Chassis.slip/ground/turn/stuck`（四套只读观测约 91 个标量，不参与控制）、`speed_kalman` 和六组 PID state（约 60 个滤波器内部量）。

K 矩阵不在 `Chassis` 里，它是 `chassis_control.c` 的文件静态量 `lqrK`，每周期由 `leg[].L0` 重算。判断拟合输入是否被夹紧看 `Chassis.leg[].K_L0_fit` 和 `Chassis.lqr.limit_flag`。

## 1. 遥控拨杆分配

右拨杆管「允不允许动」，左拨杆管「动起来做什么」。

| 右拨杆 | 行为 |
|---|---|
| 下 | 急停，输出立即封锁（`remote_stop_flag = 1`） |
| 中 | 零力矩待命，电机全软可搬运摆姿态 |
| 上 | 运行，左拨杆的模式生效 |

| 左拨杆（右拨杆在「上」时生效） | 模式 |
|---|---|
| 上 | `STEP` 跨越台阶 |
| 中 | `FOLLOW` 站立平衡、遥控移动转向，含倒地自起 |
| 下 | `TOP` 小陀螺 |

> **左中的自起是「切入时判一次」**：拨进左中的那一拍如果姿态不满足（pitch 过大或腿杆角超出准备区间），自动走 `FALLEN → FALLING_TO_STAND → STANDING`，全程 `mode` 保持 `FOLLOW`，不用再碰遥控器。
> 但**站立途中摔倒不会自动重爬**——姿态保护把状态打到 `CHASSIS_ZERO_FORCE`，而 `mode` 没变就没有边沿，要重新自起必须把拨杆拨走再拨回左中。这是有意保留的行为，不是 bug。
>
> **左下小陀螺不自起**：躺倒时拨左下会停在零力矩并置 `CHASSIS_FAULT_CONTROL`，得先回左中站起来。
>
> **⚠ 自起时"窝着的腿蹬一下"是正常的，不是 bug，别去改。**
> `theta = phi0 − phi0_offset + theta_b` 是相对**大地**竖直的角。两腿分居大地竖直
> 两侧时（例如实测到的 `phi0 = 0.9` 与 `3.14`，对应 `theta = −0.67` 与 `+1.57`），
> 而 SWING 要求两腿 `theta` 都落进同号窗口 `[theta_min, theta_max]`，于是**必然有
> 一条腿要穿过 `theta = 0`**。穿过那一刻腿处在 `extend_L0 = 0.35` 最长态、轮子踩地，
> 机体被撬起——这就是那一蹬。伸到最长再摆是刻意的（长腿力臂大才撬得动机体，
> ZJU 的 Swing 同样伸到 `lmax`）。
> 它只随 `theta_b` 的符号在两条腿之间换，不会消失：`theta_b = 0` 时是窝腿走
> 1.62 rad 穿竖直，`theta_b = −0.5` 时改成后腿走 2.02 rad 穿竖直。
> **嫌动作猛是降 `recovery.rotate_rate`（现 4.0）的事**，和卡滞屏障无关——屏障在
> `phi0 = 0.4`，而穿竖直发生在 `phi0 = phi0_offset − theta_b ≈ 1.57`，是两个不同的角。
>
> **左上跨台阶是循环的**：跨完一级自动回到 `CHASSIS_STEP_PREPARE` 等下一级，只有拨杆离开左上才退出。四个阶段已取消超时，卡住时自己拨走重试即可。

**重排拨杆只改 `remote_input.h` 里那四行 `REMOTE_MAP_*` 宏**，不要动 `device_dr16.c`。可填任意 `REMOTE_MODE_*`（`BENCH` 的控制代码还在，只是当前没绑定档位）。

摇杆：左摇杆 Y = 前进速度（TOP 下左摇杆 XY = 二维平移），右摇杆 X = 偏航角速度，拨轮 = 三档腿长。

> **右中是万能出口**：`CHASSIS_MODE_ZERO_FORCE` 有最高优先级，会同步 `last_mode` 并清 `fault`。任何卡死状态拨到右中都能把车拉回零力矩。开机建议停在右中。

## 2.5 ⚠ 气弹簧（2026-09-12 新装）——上车前必做

每条腿一根 350N 气弹簧，跨膝关节接在 `l1`（靠髋）和 `l2`（靠膝）之间。
补偿已实现并默认**开着**（`Chassis_Config.spring.enable_flag = 1`）。

### 为什么不能关

关掉补偿不等于"回到没装弹簧"：弹簧仍在物理上顶着腿，而控制器对这 100N 一无所知，
只能靠腿长 PID 的反馈硬扛。`kp = 600` 要配出约 **18cm** 的腿长偏差才平衡得住，
腿会直接坐到机构限位上。**装着弹簧就必须开补偿。**

### ✅ 选型复核：这根弹簧选得很准（2026-09-12 修正）

单腿 F0 需求 **97.5 N**（`0.5 × body_mass 16.43 × 9.81 × F0_gravity_scale 1.21`），
弹簧折算给出 **87~111 N**，正好是需求的 **90%~114%**。电机只补 ±14 N，
**站立关节力矩从 10~14 N·m 降到 0.3~1.9 N·m，差一个数量级**。

⚠⚠ 本节早先写的"偏硬 3.3 倍、站立时电机要反向拉腿、理想标称力 103~130 N"
**全部作废**。那是拿 `body_mass = 6.7` 算的，而 6.7 是从被 2.67 倍放大过的命令值
反推的假数（见 §6 的 TMAX 陷阱）。整车称重 20.8 kg 定死 `body_mass = 16.43` 后结论反转。

**教训**：判断"弹簧太硬/太软"之前，必须先确认 F0 需求那一侧的数字是可信的。

### ⚠⚠ 力矩标度已修正为 ±40，气弹簧必须排在重整定之后

2026-09-12 查明电机 TMAX 一直是 **40**，而固件是 ±15/±25（详见 §6 那段），
所以此前所有力矩和 `Fn` 读数都被缩放过。固件已改成 **±40**，与电机对齐。

**气弹簧补偿是纯前馈，没有反馈能救它的量级错误**，所以 `spring.enable_flag`
现在是 **0**，这是有意的。三条前置条件缺一条都不许开：

1. `APP_DM_TOR_MIN/MAX` 已与电机 TMAX 对齐（= ±40，**已完成**）
2. `model.body_mass` 已用**整车称重**重新定死（不再从力矩反推，见其注释）
3. `observer` 那一组力类比例阈值已在正确标度下重标

在错标度下开补偿会怎样：意图 `F0 = 33 − 109 = −76 N`，±25 时实际输出 −122 N，
净剩 −13 N，机体根本撑不住。

### ✅ 行程已定案：两端都不卡

2026-09-12 实测：断电让腿被气弹簧自己顶到最长，**左腿 L0=375mm、右腿 L0=371mm**，
与 CAD 的机构极限 375.21mm 一致——**机构先到位，气弹簧没有先到底**。

由此伸长态中心距 ≥ 269.26mm；压缩端 269.26−85 = 184.26mm，而最短腿长只压到
199.88mm，余量 15.6mm。**腿长全程可用，长档没有撞硬挡的风险。**

（铭牌的"自由长度 250mm"不是两铰点中心距这个口径。要精确值就把气弹簧拆下来自由
伸展量一次——标 DM 零位时本来就得拆。）

### ⚠ 别用手去按气弹簧，按不动

单腿轴向就要 **87~111 N（9~11 kgf）**，推机体是两条腿一起 **18~23 kgf**。

更要紧的是它的推论：**零力矩下净力永远向外（弹簧 87~111N vs 机体自重最多 32.9N），
这车在没有电机力矩时站不住任何一个短腿姿态**，断电就是"叉开腿顶到最长"。所以

- 搬运、摆姿态这些原来靠手的操作，现在都做不了；
- **标 DM 电气零位（§4.1 要求腿竖直向下时 `phi1 + phi4 = pi`）必须先把气弹簧拆掉一端**；
- **上电瞬间腿在 375mm，已经在 `lqr.L0_max = 350` 之外**，K 是从边界外推的，
  而且要把腿从那里拉回来需要约 111N（≈14.9 N·m）——**这是全过程力矩最大的一刻**。

### 上电顺序（在 §12 的基础上插队做）

1. **验 `F0_spring` 曲线：把气弹簧拆一端下来**再摆腿。`F0_spring` 是纯几何量、
   只吃 `L0`、不测任何力，拆了测出来的曲线和装着完全一样，而装着按不动。
   判据：随 `L0` 单调增、落在 87~111N、无跳变。
2. 装回去，断电看腿是否被顶到最长——**这一步同时验完方向**（顶长 = 弹簧在伸腿 =
   `force` 填正值）。若反而被收短，装配拓扑与推导相反，`force` 要填负值，**先停**。
3. 架空、只开关节输出、`wheel_flag=0`、`mpc_flag=0`、**`off_ground_act_flag=0`**
   （架空 = 永远离地，不关的话 `fn_comp` 会一直推腿），扫腿长看
   `output.T_joint_req` 是否变平。
4. 站立后看 `Chassis.ground.Fn_ratio[0/1]` 是否回到 **1.0 附近**——
   **这是判断补偿量级对不对的唯一硬指标**，偏了就是 `force` 或 `r1*r2` 错了，别去调别的。
   ⚠ 这一条要求 `APP_DM_TOR_MIN/MAX` 已与电机 TMAX 对齐（= ±40，已完成，见 §6），否则反馈力矩被缩放、`Fn` 不可信。
5. 最后才重标 `observer.off_F_comp_ratio`（弹簧腾空时已经在推腿，需要的份额变小）。

### ⚠ 气弹簧会把倒地静止姿态挤到两极（影响自起）

腿被弹簧顶到最长、以约 110 N 压在地上时，`phi0 ≈ 0.9` 这类中间角是**不稳定平衡**：
竖直地面反力 `N` 对髋关节的力矩是 `N·L0·sin(theta)`，方向是让 `theta` 继续**偏离**竖直。
所以无电机力矩时腿必然滑走，滑向 `phi0 → 0` 或 `→ 3.14`。

（机理补一句：弹簧**本身**不产生 `Tp`——膝角只是 `L0` 的函数，这是补偿只有一个
`F0` 标量的原因；但它把腿顶长之后，**地面反力经由这条长腿产生了 `Tp`**。）

**后果与直觉相反**：`phi0 ≈ 0` 正好落在 `recovery.phi0_barrier = 0.4` 的下侧，所以
装上气弹簧后卡滞屏障会从"偶尔触发"变成**常态触发**，它的正确性变得更要紧。

### 📋 待做：一次台架验证，决定卡滞屏障的去留

屏障的机械前提是"伸长的腿从正前方往下转会把轮子怼进地里卡住"。这个前提当初是在
`APP_DM_TOR ±15` / 电机 TMAX 40 的错配下验的（**关节力矩是命令值的 2.67 倍**，
卡腿比现在猛得多），在正确标度下**未复验**。

测法（成本极低）：**装着气弹簧、三道输出门全关**，把一条腿摆到 `phi0 ≈ 0`，用手往下扳。

- 轮子**掘进地面卡住** → 前提成立，屏障保留，并按 `chassis_control.c` 里
  `Recovery_Swing` 方向锁的注释把那半边的帧不一致修掉
- 轮子**只是滚过去** → 前提不成立，屏障可以删；`recovery.stuck_time = 0.60 s`
  的反应式反转作为兜底，最坏多耗 0.6 s（`fallen_timeout = 8 s` 装得下）
- ⚠ 无论哪种，**收腿站起那一半用的屏障构造是对的**（剪开圆 + 展开坐标），不要牵连

### 当前 LQR 权重（在 `ABK_LQR.py:263`，不在固件里）

```python
#        s    ds   phi  dphi theta_ll dtheta_ll theta_lr dtheta_lr theta_b dtheta_b
lqr_Q = np.diag([200,  50,  200,  50,   200,      5,       200,      5,     12000,   5])
#        T_wl  T_wr  T_bl  T_br
lqr_R = np.diag([150, 150,  30,   30])
```

实测（L0=0.23、m_b=14）：最慢时常数 1.18 s、**阻尼比 0.77**、俯仰 0.1 rad 恢复 0.28 s、
峰值轮力矩 0.45（限 3.5）、峰值 `Tp` 2.04（`joint_T_limit=20`，站立已占 9.9）。

⚠ **加大 `Q[9]`（俯仰角速度权重）不会改善阻尼，只会变钝**：实测 5→1000 时阻尼比恒为 0.77
而恢复时间 0.28→0.74 s。十维模型的俯仰阻尼主要由轮子提供。想更灵敏就降 `R` 的腿摆项
（30→12 时恢复 0.21 s、`Tp` 峰值 2.9，余量仍充足）。

其他仍需人工确认的建模项（长期遗留）：

- `I_z` 缺平行轴项，约 2 倍偏小
- `cg_to_hip` 从未实测
- `target[CHASSIS_STATE_THETA_B]` 平衡点从未实测
- ⚠ `APP_RC_LEG_L = 0.38` 超出 `lqr.L0_min/L0_max = 0.10/0.35` 的 K 采样区间，拨到长档时
  拟合输入会被夹到 0.35、`Chassis.lqr.limit_flag` 置位，K 和 LESO 的 Ad/Bd/L 都停在 0.35
  的值上外推。要用这一档必须先把 `ABK_LQR.py` 的 `LM` 上限放到 0.28 重跑并同步 `L0_max`。

## 4. 闭环前的机械与参数确认

### 4.1 关节机械零位

四台电机均在对应主动杆**竖直向下**时设电气零点，因此 `p_raw = 0` 时几何角为 `pi/2`。

手动摆腿，左右处于机械对称姿态时应满足：左右 `L0` 一致、左右 `phi0` 一致、缓慢跨越 ±pi 时 `phi0_total` 连续且方向正确、停止后 `d_L0` 与 `d_phi0` 回到接近 0。

零位错误改 `angle_offset_rad`，**不能用 `scale` 补偿**。

### 4.2 五连杆参数

`l5` 是两根主动杆**输出铰点**之间的距离，不是两个 DM 电机轴距。本车用同步带把两台电机接到重合的输出轴，因此 `l5 = 0` 正确；机构改动后必须重测。

确认：五连杆交点分支与实机构型一致、正常工作区不越死点、`sin(phi2 - phi3)` 不接近 0。

### 4.3 控制周期

目标 1 ms，由 RTOS tick 算 `Chassis.dt`，越界回退到 `Chassis_Config.default_dt`。PID、Kalman、位移积分、状态机全部消费它。运行中确认 `Chassis.dt` 稳定且无持续回退。

## 5. IMU 检查

整车右手系：`+X` 前、`+Y` 左、`+Z` 上，角度和角速度按右手定则为正。标准 ZYX 欧拉角。

| 角度 | 正方向对应的实际动作 |
|---|---|
| `roll > 0` | 左侧车身升高、右侧降低 |
| `pitch > 0` | 车头降低、车尾升高 |
| `yaw > 0` | 俯视逆时针，即车辆左转 |

`yaw_total` 与 `yaw` 同向但跨 ±pi 后连续计圈。以上针对**转换后**的 `Chassis.imu`，不要用 BMI088 原始轴判断整车方向。

静止水平放置：roll/pitch 接近 0、三轴角速度接近 0、去重力后运动加速度接近 0、无明显突跳。

方向检查：抬左侧 `roll` 应为正；压车头 `pitch` 应为正；俯视左转 `yaw`/`gyro[2]` 应为正。动作停止后角速度回 0 且角度无符号反跳。

> yaw 无磁力计和外部航向观测，长期漂移。K 中 yaw 增益较大，**启用控制时必须保证目标 yaw 与当前 yaw 对齐**，否则瞬间产生大转向力矩。

## 6. CAN 与设备映射

单一真值来源是 `app_config.h`（ID 与总线注释）和 `chassis_config.c` 活动块（`motor_index`/`scale`/`ratio`）。下表是当前值：

| 物理电机 | `motor_index` | 总线 | 命令ID | 反馈ID | 控制关节 |
|---|---:|---|---:|---:|---|
| 左前髋 | 0 | FDCAN2 | `0x004` | `0x014` | 左腿 `phi4` |
| 左后髋 | 1 | FDCAN2 | `0x003` | `0x013` | 左腿 `phi1` |
| 右前髋 | 2 | FDCAN1 | `0x001` | `0x011` | 右腿 `phi4` |
| 右后髋 | 3 | FDCAN1 | `0x002` | `0x012` | 右腿 `phi1` |
| 左轮 | 0 | FDCAN1 | `0x200` 按 slot | `0x202` | - |
| 右轮 | 1 | FDCAN1 | `0x200` 按 slot | `0x201` | - |

> **右侧两台 DM 与两台 DJI 共用 FDCAN1，左侧两台 DM 在 FDCAN2。** 不是"DM 全在 FDCAN1"。
>
> `0x200` 帧的字节位置由 `APP_DJI_TX_SLOT(rx_id)` 从反馈 ID 推出，**不要写死**，否则改电调 ID 会出现"读一个轮、控另一个轮"的交叉（3.7 版本踩过这个坑）。

`D[0]` 高四位是 DM 状态位：`0`失能 `1`使能 `8`超压 `9`欠压 `A`过流 `B`MOS过温 `C`线圈过温 `D`通讯丢失 `E`过载，经 `Chassis.dm_motor[i].err_state` 上送，≥`8` 置 `CHASSIS_FAULT_DM_ERROR`。**电机报错后会自行退出使能但仍在发反馈帧，只看 `online_flag` 会漏掉这类静默失效。**

DM MIT 位置字段按 `APP_DM_PMIN/PMAX`，速度力矩按 `APP_DM_VEL_*`/`APP_DM_TOR_*`——这三组必须与电机上位机里烧写的 `PMAX/VMAX/TMAX` 寄存器**逐位一致**。

> **⚠⚠ 本车 TMAX = 40，`APP_DM_TOR_MIN/MAX` 必须等于 ±40。这个坑真实发生过，而且藏了很久（2026-09-12 才定位）。**
>
> MIT 帧里力矩是 12 bit 无量纲整数，两端各自用自己的量程还原。固件曾长期是 ±15、后来 ±25，而电机一直是 ±40：
>
> | 固件量程 | 命令方向 | 反馈方向 |
> |---|---|---|
> | ±15 | 实际输出 = 命令 × **2.667** | 读到 = 真实 × **0.375** |
> | ±25 | 实际输出 = 命令 × **1.600** | 读到 = 真实 × **0.625** |
> | ±40 | 1.000 ✅ | 1.000 ✅ |
>
> **为什么没被发现——这一条最该记住**：两个误差在往返上精确相消
> （`命令 10 → 实际 15.99 → 读回 9.99`，比值 1.0000）。
> 把 `output.T_joint` 和 `dm_motor[].torque_nm` 摆在一起对比**永远是对的**，
> 而这恰恰是唯一查不出本类错配的检查。**别再用它当证据。**
>
> **正确的查法只有绝对力参照**：架空、关节输出开、腿长 PID 稳在竖直位，
> 在**轮轴**挂一个称过的重物（如 5 kg），看 `Chassis.ground.force[0].F0` 的变化量：
> `ΔF0 ≈ 49 N` 才算对上；读到 31 N 说明还是 ±25，读到 18 N 说明还是 ±15。
>
> **不要为了"限力矩"去改小 `APP_DM_TOR_MAX`**——限力矩是
> `Chassis_Config.output.joint_T_limit` 的职责，且只有在这一对与 TMAX 对齐后，
> 那一项才是真实 N·m（之前它夹的是"满量程"，落到电机上是 40 N·m）。
>
> 连带后果：K 的**轮子两行走 DJI 电调，口径一直是对的**；**腿摆两行走 DM，被同一个
> 系数放大过**。所以历史整定里轮子和腿摆的相对增益是失配的，改对量程后要重整定。

CAN 发送不重发。上电自动请求 DM 协议使能，漏掉该帧就没进 MIT 模式。

## 7. 电机方向与极性

### 7.1 VMC 侧视坐标

- 原点在两个主动杆输出铰点中点（当前重合）。
- 平面横轴 `+X`（车头），纵轴 `-Z`（向下）；`atan2(-Z, +X)` 正方向 = 绕车体 `+Y` 旋转。
- 后传动杆 = `phi1`，前传动杆 = `phi4`；`phi0/phi1/phi4` 均绕 `+Y` 增大。
- 虚拟腿竖直指地时 `phi0 = pi/2`。
- 常见展开姿态 `phi1` 接近 `pi`、`phi4` 接近 `0`；连续角可能选等价 `-pi` 分支，**因此不要用裸数值大小关系做保护条件**。
- 上交模型和 HERO_LEG 的角度观察方向与电机公式**不能直接复制**。

### 7.2 DM 关节方向

设备层只解码 MIT 原始坐标。安装镜像由 `scale`、传动比由 `ratio` 处理：

```c
joint_scale = scale * ratio;
phi        = angle_offset_rad + joint_scale * motor_position;
d_phi      = joint_scale * motor_speed;
motor_torque_command      = joint_scale * geometric_torque;
geometric_torque_feedback = motor_torque_feedback / joint_scale;
```

该关系保证 `motor_torque * motor_speed = geometric_torque * d_phi`。

修改规则：整体反向只改该关节 `scale`；带轮齿数变了改 `ratio`（**不要用 `scale` 补传动比**）；机械零位错改 `angle_offset_rad`；**禁止在设备层、VMC、PID 或 K 里加第二个反号**。

**无动力反馈检查**：一次只动一个关节，确认只有对应 `dm_motor[i].position_rad` 和对应 `phi1/phi4` 变化；左右做镜像动作时 `phi1/phi4/phi0/L0` 应按模型对称（不能用原始电机顺逆时针直接比）；停止后速度回 0。

**极小输出检查**（零点确认后）：架空，一次只开一个 DM，极小力矩短脉冲。正的几何关节力矩应使对应 `phi1/phi4` 初始增大。方向不对先查电机模式、CAN ID 和机械阻力，**不能改 VMC 公式补偿**。

### 7.3 DJI 轮方向

反馈与命令方向由同一组 `wheel.left_scale`/`right_scale` 控制，力矩到电流用公共 `T_to_I`，左右方向只消费一次。

正方向定义为车辆沿 `+X` 前进：`Chassis.body.wheel_speed[side] > 0` 表示该轮推动车辆向前；架空正向驱动时轮胎最低点应向车尾 `-X` 运动。

检查：地面缓慢前推整车，确认左右 `speed_rpm` 进入正确数组项、`wheel_speed` 与 `side_speed` 均为正；架空后极小电流一次驱一个轮；两轮分别确认后才同时输出，两轮正命令必须同向前进而非原地转向。某侧反馈和输出同时反向才改该侧 `scale`；**只有输出反向时不要急着加第二套符号**，先核对电机、ESC 和 CAN 映射。

## 8. 十维状态与速度融合

状态顺序**固定不可重排**：

```
0 s   1 d_s   2 fai   3 d_fai   4 theta_l   5 d_theta_l
6 theta_r   7 d_theta_r   8 theta_b   9 d_theta_b
```

输出顺序固定：`0 左轮  1 右轮  2 左腿摆  3 右腿摆`。

单侧速度公式：`R*(wheel_speed + d_theta) + L0*d_theta*cos(theta) + d_L0*sin(theta)`，其中 `R*d_theta` 是轮轴定子随腿摆动的速度项（易漏）。

检查：前推车体 `d_s` 方向正确；静止时估计速度不持续漂移；左右轮同向转主要改变前进速度、反向转不应被误算为前进；yaw 跨 ±pi 时 `lqr.x[2]` 连续无 `2*pi` 跳变。

> 当前加速度测量噪声配置极大，Kalman 几乎不使用 IMU 加速度。**不能说 `d_s` 已完成速度/加速度融合。**

## 9. K 与 LQR 输出

无论目标腿长是否固定，K 输入都跟随左右实际 `L0`，**不存在固定 K 分支**。

采样区间内 `K_L0_fit` 应等于实际 `L0` 且 `limit_flag = 0`；超范围时 `K_L0_fit` 停在最近边界且 `limit_flag = 1`。区间值见 `Chassis_Config.lqr.L0_min/L0_max`，**且必须与 `ABK_LQR.m` 的 `LM` 采样范围一致**（当前不一致，见 §3）。

左右对称状态下左右 K 和输出应满足模型对称；状态微小变化不应导致输出跳变。

## 10. 支撑力与 PID

F0 装配链（`chassis_control.c` `Chassis_Control` 内）：

```
腿长PID + 横滚PID差动 + 重力前馈 + 单腿静态修正 -> Chassis.leg[side].F0
```

**`F0 > 0` 表示伸腿/撑地**（已由虚功数值验证）。HERO_LEG 用相反约定，搬公式时符号必须翻。

增益全部在 `chassis_config.c` 活动块的 `leg_length_pid` / `roll_pid` / `F0_gravity_scale` / `F0_left` / `F0_right`，本文不复制。

检查：静止时支撑力稳定不高频振荡；左右水平时两侧差值合理；车体横滚时左右差应朝恢复水平的方向变化；支撑力不长期卡在输出限幅。

> 腿长速度或 IMU 噪声大时，较大的微分和比例参数会迅速让支撑力饱和。

已知隐患：`chassis_control.c` 里 `F0_left` 用加号、`F0_right` 用减号，但两者注释相同。当前两者都是 `0.0f` 所以不显现，**整定时会咬人**。

## 11. 最终输出检查

输出许可关闭或设备故障时，请求量（`T_joint_req`/`I_wheel_req`/`T_wheel`/`leg[].F0/Tp`）**继续更新**，只有最终命令数组清零。这是设计意图，便于 Watch 观察。

打开输出后确认：所有命令受限幅约束；设备离线时最终命令立即且持续为 0；控制计算失败时 `Chassis.fault` 含对应位；无旧命令残留；单个电机命令只作用于对应电机。

每个输出通道**只有一个限幅点**（`output.joint_T_limit`、`wheel.T_limit`），不要加第二个。

## 12. 推荐调试顺序

1. 三道输出门关闭，无动力手动转电机、推整车，确认电机映射、反馈方向、IMU 坐标、连续角方向。
2. 建立机械基准，标定 DM 电气零点和 `angle_offset_rad`；重新上电复查可重复性。
3. 架空，逐个开放极小 DM 力矩和 DJI 电流，确认每个执行器输出极性。**输出方向不得用零点偏置补偿。**
4. 关闭动力，核对五连杆尺寸、轮半径、控制周期、K 采样范围。**先解决 §3 的 MATLAB/固件参数不一致。**
5. `CHASSIS_MODE_BENCH`：先只开关节位置-速度串级，再小限幅启用两路轮输出。
6. `CHASSIS_MODE_FOLLOW`：固定目标腿长，先调支撑力与 VMC 方向，再低增益站立。
7. 加低速平移和制动，确认 `s/d_s` 方向、轮速估计、轮电流方向。
8. 加 yaw 目标和原地转向，确认连续 yaw、左右轮差动符号、进入模式时航向目标无阶跃。
9. 最后加变腿长，再分别验证小陀螺、爬台阶、自救。**扩大腿长范围前必须先重新建模，不能只解除固件限幅。**

## 13. 每次上电前

- 已架空 / 用板凳 / 装保护绳
- 急停和主电源能立即断开
- 六个电机 CAN ID 与程序映射一致，DM 已进正确控制模式
- IMU 完成初始化、温控和零偏稳定
- 腿部不在机械死点或极限位置
- 输出限幅仍是当前调试阶段允许的小值
- **力矩标度**：`APP_DM_TOR_MIN/MAX` = ±40，与电机 TMAX 一致（见 §6，最容易错且最难发现）
- **气弹簧**：行程已定案（§2.5），全程不卡；但上电瞬间腿在 375mm，在 `lqr.L0_max` 之外
- Watch 确认两侧 `valid_flag == 1`、`Chassis.fault == CHASSIS_FAULT_NONE`、全部设备在线
- 现场人员远离轮子、连杆和夹伤区域
